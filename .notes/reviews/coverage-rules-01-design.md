# Coverage and rules design acceptance

Root authored [COVERAGE-01](../tasks/coverage-01.md) and [RULES-01](../tasks/rules-01.md). The foundation agent independently reviewed them against original phases 2, 3, 5 and 7 and the QUERY contract/oracle. Root resolved the product policies; the experience agent made the distinct corrections; foundation rechecked. All seven design findings are closed.

| Finding | Accepted correction |
| --- | --- |
| CR-C1 | Curation comparison uses a separately explicit all-review canonical scope with other facets/authority retained. Its pre-authority/effective counts keep event, occurrence and physical-file units separate. Ordinary selection is unchanged. |
| CR-C2 | Known supported rows and exact document counts remain separate from unknown historical/source-row totals and unknown remaining content. Absent, empty, unreadable, unsupported and mixed documents have distinct expectations. |
| CR-C3 | Authorship and membership/participation facts join by exact selected entity IDs and immutable evidence revision. Import aggregates and known author IDs cannot override uncertain classifications or prove all recipients. |
| CR-R1 | Rules protect immutable baseline resolved/possible bytes, including candidates later rejected by the owner. Confirmation/rejection cannot release baseline protection. A named-rule exception/removal has a separate impact preview. |
| CR-R2 | Original/candidate protection expands to exact resolved/typed possible layers, including shared layers. Possible relationships stay outside composition proof. Unrelated orphans remain unrelated and unsupported relationships remain disclosed limitations. |
| CR-R3 | Atomic restore deterministically derives rule/exception effects and verifies any supplied target/count/history output. Valid existing IDs alone do not establish a correct rule expansion. |
| CR-R4 | Exceptions identify exact physical original/layer targets for one rule. They release no context, untargeted resource or other blocker. Original-only and layer-only cases have distinct disclosure previews. |

The rule contract also covers recorded participation in unknown-scope conversations, all applicable blocking rule IDs, total versus newly withheld targets, typed ID collisions and one shared item/association/rule/exception history. Coverage inspection has typed targets, scope-bound cursors, exact local source resolution and stale-read rejection. Finite panel budgets remain an adapter preflight requirement.

The separate [producer design review](occurrence-01-design.md) accepts the source/proof prerequisite; this review checks its possible-layer interface alignment only. QUERY code, complete attested occurrences and the shared FILTER application contract remain prerequisites. Final small application interfaces and subsequent code review/fix/recheck are still required. These design results accept no implementation, resource measurement, complete phase, paid call or release.
