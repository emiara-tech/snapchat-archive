# RULES-01

Accepted contract after independent original-spec design review, distinct correction and recheck. Complete QUERY-01, OCCURRENCE-01 and FILTER-01 prerequisites before implementation. The original phase specifications remain binding; this contract does not accept code, measurements or a complete phase.

Originating acceptance: [Phase 5](../specs/phase-5.md), [QUERY-01](query-01.md) and its [independent oracle](query-01-oracle.md). [Design acceptance](../reviews/coverage-rules-01-design.md) records the separate correction/recheck.

## User outcome

The owner can exclude a conversation or person, see exactly what this withholds, and reverse the choice. A shared photo cannot silently bring that context into another room. Keeping a child item cannot defeat an active rule. The rule operates independently of the current room and filters.

## Boundary

Put rule preparation, target expansion, precedence and history transitions in a UI-independent application module. Accept trusted immutable baseline exported association evidence, validated current review/association state, exact scoped participation/membership facts and an explicit timestamp supplied by the application adapter. Their dataset identity and immutable source-evidence revision must agree. Return a frozen proposal or typed failure. Applying a proposal is an atomic transition from the exact reviewed snapshot to a new review snapshot. Views present the proposal and its effect; they do not compute target expansion.

Reuse typed event/occurrence/media namespaces from QUERY-01. Do not flatten them into a single ID map. Do not add a plug-in policy language, arbitrary callbacks that match evidence, provider calls or a generic command bus. Agree on the small application interface during preflight. The two variation points are current-snapshot authority and application transaction; browser storage/file saving remain adapters.

## Persistent exclusion rules

Supported rules exclude one exact conversation ID or one exact participant ID in the current dataset. A participant label or display-name match never identifies a target. Evaluate over complete current evidence, not the selected query page. Participant involvement is established by recorded authorship or separately proven membership. Observed participation and full membership proof remain different facts.

The default participant rule withholds all recorded events in each conversation where that participant's involvement is established, including owner-authored events, known groups and unknown-scope conversations with exact recorded participation. Expand their historical occurrences and all resolved/possible original targets from immutable baseline exported association evidence. Include candidates later rejected or replaced by an owner choice. A legal current confirmation can add a protected relationship; it cannot shrink baseline protection. This input comes from the producer, not rewritten workspace effective-link status or an English basis. Missing logical targets remain typed targets with no claimed bytes.

Withhold protected original bytes across all contexts. Then protect every physical layer reached from those originals by the producer's baseline resolved or typed possible base-to-layer facts, including layers of protected candidate originals. A layer shared with an unrelated permitted base remains one protected physical target; the unrelated base's original can survive with that layer removed. Derive this target set explicitly before calling QUERY-01. Ordinary effective supporting resources alone do not establish the default rule's protection closure.

OCCURRENCE-01 must preserve known possible base-to-layer facts separately from `QueryEvidence.supportingLayers`, which contains resolved composition proof. Each possible fact identifies exact available base/layer physical IDs, evidence revision, supported candidate-rule version and attributed source references. Use only the current supported overlay candidate/source facts. Do not add a format or infer relationships from labels, nearby times or path similarity. Possible facts protect bytes conservatively and never authorize composition or confirmed history. An unrelated orphan layer stays unrelated. An unknown unsupported relationship remains an explicit protection limitation; do not promise complete protection for it or silently deny every unresolved layer. If that limitation affects the requested rule, disclose it in the impact preview before Apply.

Count confirmed originals, possible original candidates, resolved support layers, possible layer relationships, unique protected layer bytes and context occurrences separately. Multiple protected relationships to one layer produce one physical deny target. A candidate original is never counted as a confirmed attachment or recipient.

Incomplete membership is a limitation, not proof that the participant was absent. The preview lists the affected proven direct/group scopes and explicitly warns about unrelated scopes whose membership remains unknown. Do not assert every interaction with a person has been found. No rule silently excludes arbitrary unknown conversations without a reviewed target choice.

Rules remain active when filters change, review mode opens, an item is kept, or an association is changed. Reevaluate from the same immutable baseline plus validated current state. Confirming one candidate, rejecting another or undoing that owner action cannot release the baseline-protected candidate bytes. Release requires a separately previewed named-rule exception or rule removal. The preview may say a baseline possible relationship is currently rejected; it cannot present that relationship as confirmed history. Changes to evidence/schema/fingerprint invalidate old application authority until restoration compatibility is checked. Deny targets and all applicable blocking rule IDs are explicit frozen outputs consumed by QUERY-01.

## Preview and apply

An impact preview contains a stable proposal ID, dataset fingerprint and evidence version/revision, query/review revisions, exact target rule, exact typed expanded IDs, prior decision/rule state and separate effect counts. Count affected conversations by direct/group/unknown scope and membership/recorded-participation basis, event authorship, occurrences, unique physical originals, unresolved candidate files, shared physical originals and layers. Show total rule targets separately from newly withheld targets when another rule already blocks some evidence. Do not sum those populations as a number of memories. A shared original or layer is one file with its relationship counts retained. Use exact selected IDs and evidence-revision-scoped facts; import aggregates cannot supply authored-event or membership labels.

The preview freezes its IDs. Changing query, review or association state makes it stale; apply refuses with no mutation and asks the application to prepare a fresh preview. Replaying a used proposal fails. Closing/canceling applies nothing. A forged/cloned/edited proposal has no apply authority. An apply failure publishes no partial rule, decisions, history entry or revision.

Applying the participant/conversation rule adds the rule and its exact effect snapshot without rewriting original evidence or manufacturing item decisions for every child. Independent explicit item decisions retain their state beneath a blocking rule, so removing that rule reveals the correct prior item choice.

## Exceptions and precedence

An item keep/later choice does not override any applicable exclusion rule or explicit item exclusion. Denial is the union of every active rule's protected typed targets after removing only that named rule's explicitly approved physical exceptions, plus explicit applicable item exclusions. Retain every blocking rule ID. One rule's exception cannot cancel another rule or an item decision.

Deliberate exceptions are separate reviewed changes to one named rule. Their minimal targets are exact physical media IDs, with original/layer roles validated against current immutable evidence and shown separately in the frozen preview. This slice permits no event, occurrence, conversation or participant exception. Original release does not release any untargeted layer or candidate original, and layer release does not release a base or another layer. Never expand an exception through associations. A general bypass switch is outside scope.

An original-only exception may release that shared file's other permitted context while the excluded event/conversation/occurrence stays blocked. It must not add an excluded occurrence's date, text, source references, recipient or candidate proof to ordinary selection. All protected layer composition edges remain absent until an exact layer is separately excepted. A released uncertain original remains uncertain and can be selected as inventory only under QUERY-01's existing rules; release does not confirm its reference.

The preview explains that released original pixels and embedded metadata may disclose excluded context. It does not claim sanitization of original bytes. A layer-only release carries its own disclosure warning and remains subject to every other blocker. Full exact exception behavior and its minimal public shape must pass independent review before implementation; the default-rule slice can keep exceptions visibly unavailable and leave the full Phase 5 gate open.

Changing/removing a rule has its own impact preview and history entry. Present every active blocking rule when an item cannot enter the effective collection. The user can change that rule through a reviewed action. No child action silently edits a rule.

## History and persistence

Use one shared review history for item choices, associations, rules and exceptions. Store decision/action IDs, scope, explicit supplied timestamps, before/after review state and exact typed effect snapshots/counts. Undo restores that transaction's prior review state; redo restores its exact after state. Do not add an independent rule stack that could erase a newer item or association action. A new applied action after undo clears redo. Ordinary query changes remain outside review history. FILTER-01's explicitly labelled whole-state restore remains one transaction including its query.

One applied transaction increments the review revision once and recomputes the canonical collection through FILTER-01's shared adapter. The canonical query and its revision stay unchanged unless the explicitly reviewed whole-state restore changes them. The review transition invalidates affected profile drafts, observations, exports, resolver previews and owned media resources. A no-op publishes no history entry or new revision. Archive reset/replacement clears authority/history and releases stale resources. Undo/redo never reads or changes source ZIP bytes.

Saved review state includes versioned typed rules, exact physical exceptions and minimum identity metadata under FILTER-01's explicit save/restore privacy contract. The restored file is untrusted. Validate fingerprint/schema/evidence and all baseline rule/exception facts, then deterministically derive its typed denies, reasons and effect counts from immutable baseline plus the validated restored association/review state. Never use an imported denial list as authority. If a file supplies derived targets, effects or counts, require exact agreement with that derivation or reject the entire restore. If history is serialized, verify each effect against that entry's recorded before/after state and recorded scope, not today's current effects. Do not silently repair or drop inconsistent fields.

Unknown rules, impossible targets, role/proof mismatches, conflicting decisions, stale association evidence or unsupported version-4 state reject before any installation. Validate through the same FILTER-01 prepared whole-state transaction, including the full canonical query, and commit once. Do not add a later partial rule-restoration pass. No proposal authority survives serialization. Storage failure and rejected restores preserve choices, rules, exceptions, query, history, revisions, previews and resource leases.

## Independent base example

Use owner, participant P and participant Q; direct conversations CP and CQ; group CG with recorded P participation and incomplete membership; unknown conversations CU and CXP; and separately proven group CPG. CP contains owner event E1 linked to file A and P event E2. CQ contains Q event E3 linked to the same A. CG contains owner E4 and P E5 linked to file B. CU contains owner E6 with no P evidence. CPG contains owner E7 with independently proven P membership. CXP contains P-authored E8 but no scope/membership proof. A also has a Memory occurrence MA and an exact support layer LA. B has an exact support layer L. E2 has a baseline unresolved candidate reference to D/F. All physical files have distinct entries. Keep literal expected target sets and counts in the test, not computed with production expansion.

Default excluding P targets conversations CP/CG/CPG/CXP and events E1/E2/E4/E5/E7/E8, their reference occurrences, physical originals A/B/D/F and layers L/LA. CP/CG/CPG/CXP give respectively direct/group/group/unknown scope, with recorded participation and proven membership distinguished. Shared A's CQ occurrence and MA are withheld as bytes despite those contexts not being excluded events. E3's text survives with no A attachment. E6 survives with an honest membership limitation. Candidate D/F withholding is possible association protection, never a confirmed recipient claim. Confirm D, reject F or undo either choice: both remain protected by the active rule. Releasing A from this rule through a reviewed original-only exception preserves permitted E3/MA context, keeps E1/its occurrence/proof blocked and keeps LA unavailable. A second rule or explicit A exclusion still blocks A. Keeping E1 or A cannot override the participant rule.

For the separate layer case, add permitted original C used by CQ event E9 and a second independent proven C-to-L edge. Add exact producer facts for possible B-to-LP, and orphan LO with no possible base. Add a proven D-to-LD edge while D remains an original candidate. The default P rule protects B, D, L, LP and LD, leaving C original available without L composition and leaving unrelated LO untouched. L has two resolved relationships but one protected physical target. LP is a possible layer, never composition proof. A named-rule layer-only exception releases exactly L if no other blocker applies; LP and LD stay protected. An unknown unsupported relation is a stated limitation, not an invented LO association.

## Verification

Test prepare/apply and immutable transitions with literal typed targets and effect counts. Cover frozen preview targets, stale query/review/association/evidence, typed ID namespace collisions, replay/forgery, canceled preview, failed atomic transaction, known/incomplete/unknown membership, shared/candidate/resolved/possible-layer resources, exception precedence, exact undo/redo, new-action redo clearing, no-op revision and versioned restore rejection. Original input snapshots must remain byte-for-byte unchanged.

Restore regressions keep the matching identity/version but remove protected A from a saved derived effect, add unrelated valid E6, alter a saved exception to another valid layer without its matching verified effect/proof, or falsify counts. Each rejects with no rule, decision, query, history, revision, preview or lease mutation. A valid source-order-independent restore recomputes exactly the same typed denies. Verify saved history against each exact before/after state rather than merely recomputing current effects. The validator establishes consistency, not cryptographic authorship of a private file; restoration itself remains an explicit owner action.

History regressions interleave a rule action, item decision, owner confirmation and exception. Undo/redo follow that one shared order without erasing a later unrelated action. A new action after undo clears redo; failed/no-op actions create no entry. Query changes invalidate proposals but do not become rule history. Two overlapping rules retain both blocker IDs and distinguish total from newly withheld targets.

Implement one bounded behavior red to green through public application seams with independent literal expected sets. Necessary refactoring belongs to review/correction. Actual-import browser checks preview/exclude a participant, inspect the exact impact and unknown-scope warning, navigate Library/conversations/Observatory/year/export, keep a blocked child, confirm/reject a protected candidate, inspect all blocking rules, undo/redo, save/reimport with ZIP order reversed, and reject changed or internally inconsistent saved evidence. If exceptions are enabled, test original-only and layer-only release separately and retain excluded occurrence/proof canaries. Ordinary labels, examples, resources and network requests contain no excluded-context canary. Exercise resource release and stale work. No provider, public fixture or demo route. Run build, all units and affected browsers; independent original-spec/standards review, a distinct fixer and reviewer recheck precede acceptance.
