# COVERAGE-01

Accepted contract after independent original-spec design review, distinct correction and recheck. Complete QUERY-01, OCCURRENCE-01 and FILTER-01 prerequisites before implementation. The original phase specifications remain binding; this contract does not accept code, measurements or a complete phase.

Originating acceptance: [Phase 2](../specs/phase-2.md), [Phase 3](../specs/phase-3.md), [Phase 5](../specs/phase-5.md) and [Phase 7](../specs/phase-7.md). [Design acceptance](../reviews/coverage-rules-01-design.md) records the separate correction/recheck.

## User outcome

The owner can answer what their selected files actually preserve, inspect the evidence behind a limitation, and understand why a room has little or no material. Coverage describes recorded evidence. It cannot establish that a person was inactive, a conversation never happened, or an exported interval is complete.

Import coverage and the current collection are different scopes. Import coverage inventories all selected local evidence, including material later excluded. Ordinary selected coverage uses only the current effective collection. The user deliberately opens the import inventory to inspect material outside that collection. An exclusion does not become a missing export record or change the original source inventory.

## Implementation boundary

Add a pure coverage module consuming normalized source/section facts, exact per-event authorship and per-conversation scope/membership/recorded-participation facts, and the accepted canonical collection projection. All facts carry the same validated dataset identity and immutable evidence revision. It returns versioned scope-tagged summaries and opaque typed evidence targets. A browser adapter resolves an explicitly opened evidence target against the active local archive. Views render summaries and ask the adapter to open or page evidence; they do not count or classify records themselves.

Join authorship only by exact selected event ID and conversation facts only by exact selected conversation ID. A missing or contradictory fact cannot become verified ownership, other authorship or complete membership through an import aggregate or a matching display name. Reject inconsistent joins or retain an explicit unknown fact where that is the producer's recorded classification. `authorId` alone cannot override an event's unknown/conflicting authorship classification. Never copy import-wide uncertain-author counts into an effective summary or treat observed authors as every event's recipients. Deliberate import inventory may summarize its full populations.

Keep ZIP reads, Vue, Pinia, DOM, storage, network, clocks, provider calls and renderer code out of the pure module. Prefer one preparation function and one bounded evidence-page function over a registry, rule framework or multiple caller-specific calculators. Test through the preparation/page interface and actual browser import/inspection. Agree on the final small interface during task preflight against the frozen occurrence and filter types.

## Source and section inventory

Retain an exact source reference for each successfully read JSON document, unreadable document, unsupported document/field/row and physical file diagnostic. Duplicate ZIP entry names are separate physical entries. A parse failure identifies its document, not a fictitious row pointer. Malformed individual rows identify their actual pointer. Empty recognized containers have source evidence and zero supported records.

A section describes document presence, readability and supported interpretation separately. Derive a readable summary state without losing component counts: absent, fully unreadable, wholly unsupported, partially usable and supported empty/usable. Several documents can disagree. A supported empty document plus an unreadable duplicate must not be reported as fully supported empty. Distinguish source-row counts, logical normalized event/occurrence counts and physical file counts. Byte-proven duplicate copies add provenance counts without multiplying the logical count; genuine repeats and overlapping different documents remain logical records under OCCURRENCE-01.

Represent known supported source rows separately from unknown remaining content. Exact document counts and known supported-row counts are nonnegative integers. An interpretable total source-row count is nullable and may be published only when the selected documents establish the relevant supported row interpretation completely. Carry an explicit unknown-content/interpretation limitation when that total is unavailable. An unreadable document has unknown row content, even when it adds zero normalized records. A wholly unsupported shape has no established historical-row count. Neither becomes an empty export. An absent section has zero selected documents and no established historical-row total; a recognized valid empty container has a known zero total. An empty supported document plus an unreadable duplicate is partial with zero known supported rows and an unknown remainder. Do not estimate the remainder or a completeness percentage.

Recognized source categories are account, friends, chats, snaps, Memories and retained story evidence. Unknown JSON and unknown non-JSON files remain in the inventory. Known file MIME/kind is a capability label, not proof that the browser can decode that codec. Stories are not conversation events until a supported interpretation is implemented. Remote URLs and credential fields never become playback or inspection links.

## Coverage summaries

Return the calculation version, dataset fingerprint, normalization/occurrence version, evidence revision, query/review revision where applicable, timezone, and explicit import, effective-collection or curation-comparison scope. Each scoped packet includes its population definition and permitted evidence targets. Reject inconsistent revisions or malformed/dangling evidence references before publishing a summary.

For each proven historical origin, report separate event and media-occurrence totals, exact dated counts, recorded-date-only counts, and unavailable time by reason. Preserve original precision and use canonical exact instant values for selected-zone calendar membership. A date-only record stays separate from timezone-bound instant activity.

Observed periods contain only periods with eligible dated evidence and exact typed evidence IDs. Report first/last recorded instant and observed calendar-day/month counts separately by population. Do not manufacture a dense zero-filled calendar and call its blanks inactivity. A gap between observed months has unknown meaning. There is no completeness percentage or estimated count of lost events.

Report physical originals, supporting layers, orphan/unresolved layers, missing logical media records, and unresolved reference occurrences as separate populations. A missing file can be referenced by several historical occurrences; these counts stay distinct. An unsupported decode/transform is a capability limitation, not missing bytes. A candidate mention does not give a physical inventory file a year, person or confirmed history.

Report unknown and conflicting authored events separately from verified owner and other authored events, using the exact selected event facts. Conversation facts distinguish direct/group/unknown scope, proven membership, membership completeness and recorded participation, with exact source evidence. A recorded group title keeps group scope while incomplete membership stays incomplete. A conflicting event stays conflicting even if its recorded author ID matches a known participant. A group title or an observed author's presence does not establish every recipient. Explain an unavailable owner-language/year room with supported scope/identity facts, not an invented owner or a fictional preview.

Selected summaries may offer a separately explicit curation-comparison scope. Prepare its canonical query through QUERY-01 with all review statuses, keeping every other current facet, timezone and evidence/query/review authority. Its QUERY-01 matched population is the comparison before exclusion authority; its effective population is the comparison after authority. Calculate separately labelled withheld differences within each population unit. Do not subtract ordinary active-review matched/effective counts, silently change the current selection or present comparison numbers as ordinary selected counts. The user can inspect the comparison's query and units. Use the accepted collection operation for both populations rather than another coverage matcher.

Ordinary summaries and comparison packets must not include excluded names, text, source paths, proof references or raw context. Comparison counts can disclose only their explicitly named aggregate populations; excluded contributors require deliberate review inspection with that scope's authority. Import-level unsupported evidence remains in the explicit inventory rather than ordinary profiles, exports or scenes. Unowned diagnostics remain review-only.

## Evidence inspection

Every limitation category can open its exact contributing evidence IDs through a bounded page in its authorized scope. Targets distinguish source-document, diagnostic, event, occurrence, conversation and physical-media namespaces; none is implicitly an event ID. Pages carry the summary revision and a cursor tied to the dataset/evidence/query/review authority and scope, including the explicit comparison query when used. A cursor from another authority or scope fails safely even if its numeric position remains in range. Changing the archive or collection clears the inspector and cancels pending reads.

Use pages of at most 50 targets and a bounded read-only source panel. Freeze finite per-panel decoded-byte/text limits during adapter preflight, reuse current local reader/record limits and report truncation explicitly. A page target limit alone does not bound a source document's bytes. Do not copy full raw history into summaries or build another full-history cache. The source adapter validates the ZIP part/entry ordinal/path and record pointer before reading and checks the complete scope authority both before and after the asynchronous read. It selects the exact duplicate occurrence, never a first filename match. It displays inert redacted fields and the local source locator. Unsupported/malformed source text is bounded and inert; no HTML, image URL or link auto-executes.

An inspector distinguishes inability to read a local entry, missing pointer under changed evidence, unsupported shape and deliberate cancellation. It does not silently display a different row. Closing/replacing/navigating away releases its owned reads/resources. No external request is needed to calculate or inspect coverage.

## Independent fixtures and checks

Use small synthetic documents with literal expected counts and source locators. No public fixture mode or demo factory.

1. Memories-only, media-only, chats-only and a supported empty history have different limitations and available actions.
2. Absent input has zero selected documents and no established historical-row total. One recognized empty document has one readable supported document and a known zero row total. One invalid JSON document has one unreadable document, zero known supported rows and an unknown row total. One readable unsupported shape has one unsupported document and an unknown historical-row total. Empty plus unreadable duplicates have two documents, zero known supported rows, an unknown remainder and partial state. Mixed supported/unsupported rows and conflicting documents retain their distinct facts without invented totals.
3. Byte-proven copied documents add provenance only; equal sanitized rows from different bytes and repeated rows within one document retain their distinct logical identities.
4. One original used in two events and a Memory yields one physical original and three occurrences. A missing logical file used twice yields one missing record and two references.
5. Candidate-only originals, resolved support layers, orphan layers and unsupported physical files never acquire invented historical periods.
6. UTC and Europe/Oslo year/day boundaries, negative microseconds, invalid/unzoned/absent time and known date-only evidence produce literal expected calendar memberships.
7. A gap between two observed months remains unavailable evidence. Empty supported history is not absent history.
8. The import has four authored events classified owner, other, unknown and conflicting. Selecting only the owner event reports owner=1 and all other authored populations=0. Selecting only the conflicting event reports conflicting=1, including when its recorded author ID matches a known participant. Unknown account, contradictory sender fields, recorded group title with incomplete members and recorded participation retain the exact scoped limitation and eligibility. Mismatched evidence revisions or dangling fact joins reject before a summary publishes.
9. An excluded source can be deliberately inspected in import inventory but appears nowhere in ordinary effective coverage text, targets or resource metadata. Restore/undo updates scope revisions and summaries.
10. Duplicate entry paths open the selected exact occurrence and pointer. Malicious markup, remote URL/credential canaries and oversized unsupported content remain inert and bounded.
11. More than 50 diagnostic targets page without omissions/repeats. A changed archive/query rejects a stale cursor and late source response.
12. E1/A and E2/B belong to one conversation, with E1 explicitly excluded and current reviews active. Ordinary effective coverage is one event, one occurrence and one original. The explicit all-review comparison is two events/two occurrences/two originals before authority and one of each after it, with the same other facets and timezone. If both events reference A, comparison originals are one before and after while occurrences are two then one. Switching comparison scope does not mutate the ordinary query. Narrowed keep/later reviews follow the same separate all-review comparison contract.
13. A deliberately opened inventory/comparison evidence panel uses its own typed scope authority. A source/diagnostic target cannot resolve as an event, a cursor from another scope cannot resolve by numeric position, and a late read cannot publish after authority changes. Unknown-row, authored-event and withheld units never combine into one claimed historical total.

Implement one bounded behavior red to green through the public preparation/page interfaces, using independent literal expectations. Necessary refactoring belongs to the review/correction stage. Run affected units, the full existing unit suite, build and actual-import browser checks for source selection, paging, empty-room explanation, comparison separation and cancellation. Inspect browser errors and network requests. Record only aggregate private verification, if used. Independent spec/standards review, a distinct fixer and reviewer recheck precede acceptance. Full worker/performance, observation and release gates remain separate.
