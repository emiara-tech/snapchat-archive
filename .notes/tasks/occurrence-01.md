# OCCURRENCE-01

Accepted producer contract after independent design review, distinct correction and recheck. Bind the public types to accepted QUERY-01 code before serial implementation. The original phase specifications remain binding; this contract does not accept code, measurements or a complete phase.

Originating acceptance: [Phase 2](../specs/phase-2.md), [Phase 3](../specs/phase-3.md), [Phase 5](../specs/phase-5.md), [QUERY-01](query-01.md) and its [independent oracle](query-01-oracle.md). [Design acceptance](../reviews/occurrence-01-design.md) records the separate correction/recheck.

Stage 1's byte-proof and row-identity code is accepted at `d88c7b2`. Stage 2's occurrence/reference/missing/candidate code is accepted in [the runtime review](../reviews/occurrence-01-stage-2.md), under [its exact binding](occurrence-01-stage-2.md), [literal oracle](occurrence-01-stage-2-oracle.md) and measured declaring-provenance amendment. The next serial stage binds time and participation contracts. Complete QUERY capability and the remaining producer stages stay open.

## Value and bounded outcome

The owner can search one historical use of a photo without borrowing a date, person or caption from another use. Repeated saves remain separate. Copies of the same document add source proof without inventing more history. Missing files and uncertain references remain inspectable. Every query fact resolves to the exact local ZIP entry and row that supports it.

Deliver complete `QueryEvidence` from the existing local archive loader and normalizer. Keep the current participants, conversations, events, assets and links as the shared domain. Add historical occurrences and typed proof where the current parser has the original row in hand. Do not parse the archive a second time into another generic model, build a parser framework, replace archive readers, or wire canonical filters into pages in this task.

The evidence producer is a prerequisite for FILTER-01. This task does not complete cross-room query parity, saved-state migration, participant rule authoring, large-query workers, arbitrary export formats, supported video composition or external transfers.

## Current source and real prerequisites

- `src/lib/dataset.ts:14–26` represents a document as decoded text only. At lines 60–70, `loadArchiveDataset` reads original entry bytes and immediately decodes them. Compute the standard original-document SHA-256 at that point. The separate whole-ZIP fingerprint at lines 30–52 is a versioned SHA chain, not an interchangeable document digest.
- `dataset.ts:215–230` currently groups events by sanitized row values and repeat rank across documents. Different original documents can collapse into one event. A postprocessing adapter over `ArchiveDataset` cannot recover those lost rows. Fix this partition inside the existing normalization pass.
- `dataset.ts:294–321` attaches Memories metadata to a physical asset and overwrites its timestamp/location/raw fields. Preserve a row-level occurrence before this loss. `MediaAsset` accumulated fields cannot become query occurrence facts.
- `dataset.ts:347–376` builds event links, and `parseMediaReferences` at lines 540–546 removes repeated reference tokens with a Set. Preserve supported reference slots and their ordinal before deduplication. One file used in several slots/events remains several historical occurrences.
- `dataset.ts:184–205` and lines 256–272 mix observed authors, recorded direct recipients and owner labels in `Conversation.participantIds`. Publish membership proof separately. A group title can establish a recorded group scope without establishing its complete member set.
- `normalizeTime` at lines 397–452 preserves positive microseconds in a padded ordering string but rejects signed numeric epochs. Publish a canonical exact integer, retain date-only/unavailable distinctions and preserve DATA-02's corroborated unit rule.
- `src/lib/snapArchive.ts:81–90` passes only the reader's lifetime signal into entry reads. Dataset cancellation currently checks around a read and terminates its worker, but does not individually cancel that active ZIP read. The loader must compose its operation signal with reader lifetime without disposing a still-current session.
- `src/stores/workspace.ts:32–44` rewrites link status and an English basis for owner choices. `AssociationDecision` has no durable decision ID. Typed owner confirmation must be constructed from the actual decision and exact reference proof, never that display string. FILTER-01 owns store transaction/schema integration.

None of these prerequisites needs an account, remote model, provider key or private upload. New unsupported export variants need structural evidence and a synthetic regression before they become supported. The implementation uses synthetic original bytes through actual ZIP reads. Private evidence is optional local validation and never a committed fixture or report.

Proposed ownership is `src/lib/dataset.ts`, `src/types/dataset.ts`, `src/lib/dataset.worker.ts`, focused dataset/loader tests, and a small `src/lib/archiveEvidence.ts` only if owner-decision preparation earns that separate interface. A narrow reader-signal extension in `src/lib/snapArchive.ts` is allowed with lifecycle regressions. Reuse `src/lib/snapZip.ts`; change it only if a verified read/integrity prerequisite requires a focused correction. Do not edit query implementation/types, views, routes, export modules, inference, credentials or tracked progress without separate ownership.

Retain the public `loadArchiveDataset(session, signal)` and `normalizeArchiveDataset(input)` seams. A loader options argument may carry validated finite resource limits for tests and bounded production reads. Extend `DatasetDocument` with original document digest, actual byte length and exact entry ordinal supplied by the loader. A field inside the untrusted JSON cannot supply any of them. Verified digest fields passed to the pure normalizer are trusted loader/test DTOs. Normalization validates their shape and references; it cannot itself attest unseen bytes. Tests obtain them from their authored original bytes. A text-only fixture or digest claimed inside parsed JSON supplies no original-byte attestation and cannot enable complete query evidence.

Add one authoritative `ArchiveDataset.queryEvidence: QueryEvidence | null`, plus an explicit capability reason when complete proof is unavailable. Use the accepted public `QueryEvidence`, `QuerySource`, `QueryTime`, `QueryOccurrence`, `QueryAssociation` and supporting-layer DTOs. Do not introduce another occurrence hierarchy or query language. These types are currently authored under `src/types/archiveQuery.ts`; bind the final proposal to their frozen version.

The loader publishes baseline exported facts. A small pure preparation operation may apply validated local association decisions to that immutable baseline:

```ts
prepareQueryEvidence(dataset, associationDecisions)
  -> { ok: true, evidence: QueryEvidence }
   | { ok: false, errors: readonly safeErrors[] }
```

This operation owns typed confirm/reject projection and proof. It accepts explicit data, performs no store, storage, clock or ZIP I/O, and mutates nothing. FILTER-01 creates/persists decision IDs and invokes it before a collection transaction. Review keep/exclude/later and rule deny targets stay inputs to QUERY-01, not loader filtering. Every room can reuse the same prepared evidence.

The helper requires a durable decision ID, confirm/reject action, exact baseline occurrence/reference and candidate target, the matching link target where that identity exists, an explicitly supplied valid timestamp, and the immutable base source-evidence revision. Validate that the candidate and its attributed proof actually belong to that exact reference and occurrence. Reconstruct permitted source proof from matching baseline evidence; an untrusted decision cannot supply authority by naming arbitrary existing sources.

Reuse or narrowly extend the existing domain decision contract. New proof fields may remain optional on the existing `AssociationDecision` type for compile compatibility while its current store constructors remain outside OCC ownership. The preparation helper validates the complete required input at runtime. Missing, stale, dangling or competing proof rejects safely before producing owner-confirmed evidence. It never creates placeholder decision IDs, fills targets from an English basis, substitutes mutable review revisions or silently skips legacy decisions. Calling it with no decisions preserves valid exported baseline evidence. OCC does not migrate existing store choices or activate the new canonical application path. FILTER-01 owns creating the complete new records, their versioned persistence, undo/redo and atomic integration after producer acceptance, keeping the staged current product usable.

## Original bytes, decoding and source identity

Read each exact JSON entry using source, safe path and ordinal. Hash its decompressed original document bytes with standard SHA-256 before decoding, parsing, sanitizing or re-encoding. Retain the digest as private local evidence. Never substitute CRC, advertised size, a digest from JSON, decoded string equality or a whole-ZIP chain fingerprint.

Decode UTF-8 without replacement-character recovery for supported JSON. Invalid UTF-8, malformed JSON and unsupported shapes have exact source diagnostics and section coverage; they do not produce guessed rows. A BOM or whitespace difference changes original document bytes and cannot establish copy equality through equal parsed values. Unknown documents remain unsupported evidence, with original local access, not invented origin sections.

Retain the existing bounded whole-source fingerprint and stable physical identity rules where valid. Each physical source occurrence remains separate even if bytes or names match. Register stable `QuerySource.id` values from source fingerprint, path, entry ordinal and record pointer. `QuerySource.sourceId` resolves to the session's exact ZIP source. Runtime source handles may change after reordered selection; stable item/source-reference IDs and evidence membership do not. Keep this stable identity distinct from expiring object URLs and session File handles.

Available `QueryMediaRecord.sourceIds` contain exact physical-file evidence only, with null document SHA. Historical row source IDs belong to the occurrence and its association proof. A missing record has null entry and `available: false`; its nonempty source IDs are actual declaring-row metadata proof, matching the frozen QUERY validator. They are not physical-byte evidence. Canonical projection limits this metadata proof to selected occurrences. Use only a minimal source-backed missing label/token, never another occurrence's caption, location or first retained label. Do not accumulate unrelated historical source pointers onto an ordinary physical resource.

Supported reference arrays retain original numeric positions. For `["A", null, "A"]`, positions 0 and 2 produce two known supported occurrences; position 1 retains an exact typed malformed-slot diagnostic and unknown remainder. It cannot become a guessed token, attachment or known historical appearance. Absent and wholly unsupported fields retain the event plus their distinct reference limitation, without claiming an attested slot total. A recognized empty array has a known zero slot total. Event media kind alone does not invent an implicit reference slot.

A recognized Saved Media row has at least one own established field among Date, Media Type, Download Link and Location. Recognized fields with invalid values retain a known save and their uncertainty. Empty or unknown-only objects remain diagnostic evidence. Location belongs to its own row. No Caption/Content/Message alias becomes a caption without supported format evidence; chat Content remains event text. Preserve original local evidence when a field is uninterpreted.

Serial stage 2 may retain one readonly staged subset of the accepted occurrence/source/resource DTOs with the existing `NormalizedTime`, explicit missing-proof capability and exact row/container/reference facts. This cannot claim exact `QueryTime` or complete QUERY capability. Capture numeric array indices and exact container pointers before compaction. Object-key enumeration cannot prove textual member order across independent containers. Freeze exact field names/nullability, safe parser and legacy-ID rules plus finite incremental count/field/aggregate expansion limits before code. A reached limit rejects the whole operation safely; it cannot return an empty or partial population as complete. Measure the new fact expansion before stage acceptance without claiming a heap guarantee.

## Logical identity and version boundary

Logical row/copy identity uses identity version 1, original document SHA-256, proven document origin/path, exact row pointer, repeat rank and reference ordinal. Corresponding rows from exact original document copies merge only when all those fields agree. Retain every source copy pointer/entry ordinal as provenance. Repeated rows at different pointers, repeated explicit references at different slots, overlapping different-byte documents and conflicting metadata remain distinct.

Construct rows and reference slots before credential redaction or lossy transforms. No private credential value needs to survive into an ID's clear text or normalized data. A change in an excluded credential field still changes the original document digest and prevents unsupported copy merging. The original file remains unchanged and available only through deliberate local inspection.

Preserve existing event/participant/conversation/media/link IDs where they identify the same valid evidence. For events, an old identity may be retained only if its old partition corresponds to one proven logical event. If a sanitized-row partition conflated several independent rows/documents, assign corrected versioned event identities to the split evidence instead of retaining an arbitrary first-match identity. Repeated reference slots need distinct reference/occurrence IDs and corrected link IDs where the previous token-based ID conflated them. Preserve physical IDs and ordinals without CRC/content deduplication.

Identity authority includes the dataset fingerprint, typed item ID and immutable base-evidence revision. A bare item ID does not authorize a choice across archives. Assess the whole current-input legacy partition before retaining a singleton ID; attested document copies count as one logical row. Every independently split row in a conflated partition receives a corrected versioned ID. Separately imported singletons may retain the same legacy bare ID under different fingerprint/evidence authority. Their choices and proposals cannot transfer on that ID alone. Include validated original-document proof in an unverified-source fingerprint fallback; equal parsed JSON cannot erase attested BOM/whitespace or other original-byte differences.

Use normalization version 5, or the next explicit version after the then-current version, and occurrence identity version 1. The dataset fingerprint includes the normalization boundary and attested source evidence. Same supported input with ZIP selection reordered produces the same supported item IDs, fingerprint, occurrence grouping and query order. Materially changed evidence cannot reuse a different row's identity.

Portable state from normalization version 4 must visibly reject before any decisions apply. This task does not implement compatible-target migration or bypass a fingerprint mismatch. FILTER-01 may later import explicitly verified compatible targets. Old text-only `DatasetInput` fixtures or incomplete facts must not fabricate complete query evidence; retain an explicit unavailable capability until original-byte proof is supplied.

## Historical occurrences and conservative references

Chats/snaps create one occurrence per supported exported media-reference slot. Preserve order and multiplicity in explicit arrays or supported ordered token formats. Invalid individual slots have source evidence and an explicit unlinked/unsupported diagnostic; do not attach an unrelated file. An unsupported whole field does not invent a number of attachments. No-reference events stay events with the query's no-reference unlinked behavior.

Memories creates one occurrence per recognized Saved Media row, including rows with missing physical files, invalid time or unknown media kind. An object with no supported record fields remains invalid diagnostic evidence rather than a fabricated save. Every occurrence preserves its own Date, supported caption/location literals, declared kind and exact pointer. Memories never gains a recipient/conversation from a reused file.

Use the current supported exact-reference rules and indexed local identifiers, with typed rule/version/source proof. Parsing a supported mid from a local record's remote link only extracts the safe identifier; it never retains or fetches the link. Add no similarity, time-near, caption or name heuristic. A unique supported original can be export-confirmed. Duplicate exact candidates stay ambiguous. Missing bytes stay unlinked with a logical missing metadata record where established. Available physical originals remain inventory independently of uncertainty; query selection decides inventory eligibility globally.

Candidates contain distinct available originals with candidate-specific source proof and separate reference proof. Layers and missing/unavailable records cannot be ordinary candidates. Shared references do not collapse occurrence counts. Candidate proof cannot cite another candidate's physical evidence. Unsupported reference-to-layer evidence remains explicit without confirming a layer as an original attachment.

Complete owner decisions carry the required durable ID, exact occurrence/reference and candidate targets, action, timestamp and stable base evidence revision. Preparation rejects incomplete legacy data and stale/dangling/competing confirmations before producing evidence. Confirmation constructs `owner-confirmed` proof with exact permitted reference/candidate sources. Rejection removes only the selected candidate from that reference; one survivor remains uncertain. If no candidate survives, use an explicit unlinked reference with its source proof, not a fabricated missing file. Undo restores the original snapshot's reference proof. Baseline exported resolved/possible associations, layer facts and original bytes remain unchanged for conservative rule protection; current owner rejection cannot erase those baseline facts.

## Time and participation facts

Extend normalized time with a canonical signed epoch-microsecond integer where an instant is supported. Do not reconstruct it from millisecond `timestamp` or parse a padded lexical key as the public contract. Preserve original raw fields, interpretation basis, precision, zone and conflict reason. Source time IDs resolve to the exact row/fields that established the interpretation.

Retain DATA-02's rule. A numeric field labelled microseconds is interpreted under its supported field semantics. Correct mislabeled milliseconds only when an explicit recorded zoned date corroborates them within that date's recorded precision. Magnitude, an unzoned string, date-only evidence or the computer's timezone cannot authorize that correction. Conflicts remain unavailable/invalid with evidence.

Signed -1 microsecond is exactly 1969-12-31T23:59:59.999999Z. Floor negative fractional milliseconds for display conversion and compare exact integers for order. Validate civil dates/times, declared divisibility and the supported year range. Preserve all six supported fractional digits; unsupported finer precision cannot silently truncate into a claimed supported instant. A date-only value retains its recorded date with no fabricated midnight or zone. Invalid, absent and unzoned evidence stay distinguishable in query DTOs.

Keep observed authors and recorded participation separate from proven membership. Retain existing source-backed direct/group/unknown scope classification. A proven direct thread may publish its supported owner/recipient proof. A recorded group title establishes scope, not complete membership. Observed authors can match their own events without proving historical recipients of other events. Do not fill provenMemberIds from the current accumulated participantIds array.

Record exact per-event owner/other/unknown/conflicting authorship and per-conversation membership completeness/recorded participation separately in the domain for later coverage and impact previews. Bind each fact to its stable exact entity ID and immutable evidence revision. These facts permit scoped joins without copying import-wide aggregates or filling membership from accumulated observed authors. A conservative exclusion may deliberately withhold a recorded or uncertain conversation, but its UI must not claim that a title, observed author or partial participant list established every recipient. New group membership fields require a supported export variant and independent fixture before they are consumed as proof.

## Layers, diagnostics and bounded publication

Emit distinct exact-proven base→layer edges with exact source evidence and supplied order when known. Resolved layers have no historical occurrence and no inherited date/recipient. Orphan/unresolved layers retain their own physical records. Ambiguous competition remains unresolved; the producer cannot choose an arbitrary layer. Multiple proven edges and shared physical layers are allowed. Query exclusions determine effective support resources and clear composition references.

Preserve known possible base-to-layer relationships as typed immutable normalized facts outside `QueryEvidence.supportingLayers`. Each fact has a stable relation ID, exact available original/base and layer physical IDs, the immutable evidence revision, the current supported candidate-rule version and attributed exact source references. Validate role, availability and source membership rather than accepting a dangling ID or arbitrary proof reference. A relationship pool preserves each known pair, including several competing layers for a base or several bases for one layer. Reuse existing supported exact overlay candidates and their physical/source facts. Do not introduce a new format, infer from a label or path similarity, or use `layerState=unresolved` alone as a base identity.

These possible facts are conservative byte-protection inputs for RULES-01. They never authorize composition, resolve ambiguity, create a historical occurrence, date or recipient, or modify QUERY-01's DTOs. Baseline resolved and possible relations remain available to rule preparation even after an owner edits an event's candidate choices. A protected original's resolved/possible layers can be denied across a shared permitted base without dropping that permitted original. Unknown unsupported relationships retain an explicit protection limitation; an unrelated orphan stays unrelated and cannot be silently assigned to every protected base. Keep the known-relation population and unknown limitation distinguishable from resolved support resources.

Preserve section presence/readability/support, known supported source-row counts, unknown remaining content/interpretation, logical historical counts, duplicate-copy provenance, missing/ambiguous references, unknown authors/time and unsupported diagnostics without mixing those units. Unreadable or unsupported contents have no established historical-row total, not zero. Document counts remain exact; recognized valid empty containers have a known zero row total. Parsed empty differs from absent, malformed and partially supported. Observed archive periods never become complete historical coverage.

Publish `occurrencesComplete: true` only after all recognized supported records/reference slots are processed, sources/proofs resolve and the complete DTO passes the accepted query contract. It means the supported normalized occurrence model is complete, not that Snapchat retained every historical event. Missing, malformed or unreadable sections can coexist with supported evidence only after every selected document is byte-attested and inspected, with explicit partial coverage and exact diagnostics for unsupported input. Their unknown contents cannot become zero-history claims. Skipped work because of cancellation, a resource budget, internal normalization failure or missing original-byte proof cannot become a successful complete result. FILTER-01 retains that coverage beside the effective collection.

Hash/read at most one document buffer at a time. Precheck advertised sizes and enforce actual read/aggregate limits before decoding. Retain the existing 128 MiB per-document ceiling for compatibility and provisionally add a 256 MiB aggregate JSON-byte ceiling. These are provisional safety ceilings, not measured heap or cancellation claims. Confirm them against synthetic resource measurements separately before implementation acceptance. Reject a reached limit safely with no complete publication. Do not read/decode full media merely to establish occurrences or match a reference.

Normalization runs in the existing worker for substantial input. The worker receives original digest metadata and decoded supported text, not source File handles or a second model. It publishes an operation revision and complete result only for its current owner. Cancellation/replacement aborts active entry reads, stops further hashing, terminates the worker and rejects late messages. Repeated cleanup is safe. A still-current archive session remains usable after cancellation. No archive bytes, digests, names, pointers, rows or query facts leave the device or enter telemetry.

## Testable acceptance criteria

1. Actual generated ZIP entry bytes are hashed before decoding. Two distinct invalid-UTF byte sequences cannot become copy proof because a forgiving decoder produces the same string. BOM/whitespace-different JSON documents with equal parsed rows have different document proofs and separate unproven logical rows.
2. Two identical rows in one chat document remain two events. A byte-identical copy adds two source provenances without adding events. An overlapping different-byte document containing the same row adds a third event. Sanitized credential-field equality cannot merge it. Each source opens its correct JSON pointer/ordinal.
3. Two equal Saved Media rows in one document remain two saves. Their copied document adds provenance only. An overlapping document adds another save, and a conflicting row retains its own location/caption. One physical original can serve all supported uses without multiplying physical-file counts.
4. Repeated supported reference slots preserve their original ordinals and separate occurrence IDs. Several event slots and Memories saves referring to one original produce the exact hand-authored occurrence count. Unknown/malformed slots do not attach bytes or disappear silently.
5. Same-path physical files across parts and duplicate names within one ZIP remain separately addressable by source and ordinal, even with equal advertised CRC/length. Every exact physical resource is preserved; competing reference/layer candidates remain ambiguous.
6. Signed -1/0/+1 microsecond input retains exact integers and order. Zoned strings, supported offsets, repeated DST clocks, date-only, absent/invalid/unzoned values and conflicts follow the accepted oracle. DATA-02 corroborated-millisecond regressions still pass; magnitude-only correction still fails.
7. Unknown membership with observed Maya/owner authors selects only Maya's authored event for a Maya query. A supported direct recipient proof can match owner-authored direct events. A group title does not add all observed authors to proven membership. Partial participation and completeness are inspectable separately.
8. Supported exact links produce export-exact proof. Ambiguous candidates carry attributed physical/reference sources. Complete confirm/reject/undo snapshots produce typed owner proof and preserve originals. Individually missing decision ID, occurrence/reference/candidate target, timestamp or evidence revision, plus stale/dangling/competing proof, rejects safely without mutation or invented fields. No-decision baseline evidence remains valid. Existing incomplete store choices do not break compilation or acquire owner-confirmed capability. Missing bytes remain honest metadata without a remote request.
9. Resolved video/image support layers add resources without occurrence/time inflation. Separately typed possible base/layer facts preserve every known candidate pair without composition proof. A layer L independently shared by protected base B and permitted base C remains one physical layer with two proven relationships; C's original is independently addressable. Known possible B-to-LP remains possible, and unrelated orphan LO gains no base. Current candidate choices do not erase immutable baseline protection facts. The producer preserves known multiple edges/order and exact source attribution; it does not infer missing relations/transforms or compose unsupported video.
10. A dataset with complete attested evidence satisfies the accepted QUERY-01 literal conjunction/review/candidate/layer tests through the public functions. A dataset lacking occurrence capability fails explicitly instead of approximating from asset.timestamp/raw/location.
11. Selecting only a chat/period or excluding a conflicting Memories occurrence removes that occurrence's caption/location/source canary from every complete effective query projection while preserving its original local evidence. Candidate-exclusive proof and global/owned diagnostic canaries remain scoped under the accepted oracle.
12. Reordered multipart selection preserves stable supported IDs, fingerprint, logical counts, exact proof membership and ordered results. Changed source bytes or corrected normalization identity produces the stated version/fingerprint boundary. Normalization-4 review state cannot silently apply to version-5 evidence.
13. Low-limit synthetic cases stop before unsafe decoding/publication and report the actual limit. Cancel during document read/hash/worker work closes acquired resources, prevents stale result publication and allows a valid retry. Replacement cannot receive an old worker result.
14. Actual-import desktop browsers inspect duplicate/missing/unknown evidence, exact sources and media locally with no archive-bearing network request or page errors. Build, affected units and unchanged current import/workspace/Year/Guide/export browsers pass, including staged legacy store constructors while FILTER activation is pending. Synthetic stress measurements report input size, processing/cancel response and observed resource bounds separately from full performance acceptance.
15. Authorship and membership/participation facts resolve by exact entity ID and evidence revision. A conflicting event remains conflicting despite a known participant ID. Absent, empty, invalid JSON, unsupported shape and empty-plus-unreadable duplicate inputs retain literal distinct document/known-row/unknown-remainder facts. None uses an import-wide aggregate as scoped event/membership proof.

## Delivery and review order

First freeze QUERY-01 types/code and this producer contract through independent original-spec/standards review. Then use separate author/reviewer/third-fixer loops for bounded producer stages: original-document proof plus corrected row identity; exact occurrence/reference/missing/candidate evidence; time and participation contracts; worker/read cancellation and public-loader integration. Shared dataset types/normalizer edits are serial. Each stage freezes, passes review/fix/recheck and transfers ownership before the next stage changes those files. Independent preparation in disjoint tests/modules can proceed only under explicit ownership.

Drive each stage red-to-green through `loadArchiveDataset`, `normalizeArchiveDataset`, the owner-decision preparation seam and QUERY-01's public functions. Expected rows, physical entries, pointers, ordinals and counts come from hand-authored tiny ZIP fixtures, never the production producer/evaluator. Use pnpm for targeted tests, build and affected browser checks. Do not add a public fixture factory, demo route, private data or new paid flow.

Freeze measured checks, supported rules, capability limits and remaining Phase 2/3/5 gates before handing the loader to FILTER-01. Root confirms ownership and authorizes code only after this proposal's independent review. Full state migration, canonical UI controls, rule exceptions, export consumers and release verification remain separate tasks.
