# EXPORT-03: Recoverable local bundles and independent reopening

Accepted bounded design after independent original-spec and standards review. [Phase 6](../specs/phase-6.md) and [the destination contract](../../docs/export-destinations.md) remain binding. [Design acceptance](../reviews/export-03-design.md) records the preconditions. This contract accepts no code, resource measurements, browser behavior or complete phase. QUERY/OCC/FILTER/RULES/COVERAGE/MEDIA contracts are the dependencies; their design acceptance cannot substitute for runtime capability. No destination integration, new codec, faithful composed video, public fixture mode or source-JSON reconstruction is included.

## Owner value

A damaged or unavailable item should leave an understandable receipt rather than an unexplained failed download. The owner can see exactly which originals, contexts and requested derivatives exist, retry eligible failed work without repeating successful work, and reopen every required part to check integrity. A complete available collection means the selected imported evidence under the approved policy, with explicit gaps and limits.

## Current implementation and retained guarantees

`src/lib/exportSnapshot.ts:24–73` prepares a detached legacy snapshot. It still copies aggregate conversation labels and physical-asset dates/location/sources; it is not the future canonical scoped adapter. `src/views/ExportView.vue:36–80` owns preview authority, writing, sink selection and generic errors in the page. Complete preview explicitly resets shared filters. Preserve that disclosed behavior through FILTER rather than silently changing scope.

`src/lib/exportBundle.ts:111–124` freezes the current plan and estimates bytes. `:167–275` reads exact originals/layers, checks approved source sizes, writes payload SHA-256, preserves separate originals, composes only the established static image capability, and adds omission text for unavailable derivatives. A failed original read stops the operation. `:295–314` records emitted parts and refuses a completed catalogue after failure, but has no structured receipt for every planned target. `:317–354` releases one browser download source through its bounded handoff interval. That interval never proves a saved disk file.

Retain EXPORT-02's exact source/path/ordinal resolution, zero-byte size checks, original/layer validation before flushing subsequent work, 64 MiB item and bounded part checks, pre-decode source/pixel budgets, unsupported recorded-transform refusal, shared versioned composition, incremental part backpressure, once-only URL cleanup and cancellation semantics. Existing tests in `tests/exportBundle.test.ts`, `tests/browserDownload.test.ts`, `tests/exportSnapshot.test.ts`, `e2e/export-review.spec.ts` and `e2e/composition.spec.ts` remain regressions.

`tests/largeExport.test.ts` exercises more than two GiB through a generated repeated source buffer and a Node sink. It measures a sampled Node RSS increase under its asserted ceiling. It is useful existing evidence, but does not establish real ZIP import, browser memory, actual disk reopening or every complete-bundle scale gate.

## Prerequisites and small application interface

OCC supplies complete original-byte-attested occurrences, reference multiplicity, typed exported/owner proof, exact physical entries and immutable resolved/possible association facts. FILTER supplies one canonical collection and complete session/dataset/evidence/query/review authority, scoped title/name values and exact field proof. RULES supplies validated baseline conservative physical protection and narrow exceptions; COVERAGE supplies scope-tagged limitations; MEDIA supplies exact resource acquisition and the existing static composition capability.

Pure application tests may use complete hand-authored evidence. Runtime activation must wait for these accepted producers/adapters. A legacy flat asset or cast cannot satisfy them. Until available, keep the current exporter usable and describe this proposal as pending.

Keep preparation, receipt transitions and retry eligibility outside pages. Reuse the existing `prepareExportSnapshot`/`createExportPlan`, writer, composition and local sink boundaries. Freeze a small concrete interface before code, along these operations:

- Prepare an immutable approved export plan from one effective collection, scoped label/context projection, policy and current authority.
- Write that exact plan through the existing exact-entry reader and bounded local sink, returning a structured receipt on success, failure or cancellation.
- Prepare an explicit eligible failed-target retry from that frozen plan/receipt and the same current authority, or safe errors.
- Independently verify reselected saved parts/catalogue against the expected plan/receipt and declared payload inventory.

These are domain/application operations and I/O adapters, not a second matcher, job framework, command language or archive model. A view renders prepared scope/status and dispatches these operations. Do not add writer-side record filtering or derive permission from a physical filename/path. Bind exact type and function names to the accepted FILTER/MEDIA interfaces during ownership preflight.

## Scope and frozen plan

Curated mode consumes the ordinary effective population. Complete preparation explicitly resets temporary shared filters through the existing disclosed FILTER action and freezes the resulting permitted population. It retains all applicable item/rule/physical denials. A complete plan cannot inherit an unseen narrower filter or secretly include excluded context. Including exclusions is outside this slice unless an existing independently accepted narrow RULES exception/removal is explicitly previewed first.

Freeze session, attested fingerprint, normalization/occurrence/matching versions, immutable base-evidence revision, dataset/query/review revisions, canonical query/timezone, mode, disclosure/variant policy, exact event/occurrence/media/support IDs, source entry identities/roles/approved sizes, permitted labels/proof, safe output paths and estimates. Baseline possible associations remain conservative protection facts, never composition or asserted history.

Capture full authority before preview preparation, file reads, rendering and sink work; check it before and after asynchronous stages and before publication. A real dataset/query/review/rule/association/session/policy change invalidates approval, stops work and rejects late results. Equivalent no-op FILTER changes preserve approval. A local reopened bundle or imported receipt never authorizes a source read, review restoration or changed plan by itself.

Repeated uses retain all distinct permitted occurrences and contextual links while physical resources can be written once. Candidate-only originals may be ordinary independent inventory under QUERY rules, labelled as standalone bytes. Their uncertain references remain separate; no date, recipient, inline attachment or confirmed history is manufactured. Deliberate review/matched/global-diagnostic payloads are not cleaned export input.

## Context privacy and byte preservation

Every generated record, label, path, page, sidecar, thumbnail, proof reference, omission and receipt follows the same effective scope. Use FILTER's chosen title/name plus value-level proof or its neutral fallback. Use each occurrence's own timestamp, caption/location and reference proof. A selected file does not authorize all accumulated historical metadata or a conversation's aggregate label history. Parent row context is permitted only under the accepted effective occurrence projection; another row sharing the conversation is not permission. Keep the exact canonical query private in the approved plan for authority. Output a disclosure-permitted query/policy summary or opaque digest; do not automatically serialize search literals, denied target IDs or review/rule definitions into a cleaned manifest.

Keep minimal physical source evidence distinct from permitted contextual proof. Generate portable filenames from collision-safe stable IDs and allowlisted MIME/extensions, retaining Unicode content inertly. Unknown or active original document formats remain explicit attachment downloads; readable pages never embed or automatically navigate into them. Source locators can themselves contain private names. Include only disclosure-permitted exact locators; otherwise use an opaque locally resolvable proof ID or flag/withhold the affected generated provenance field. Do not copy whole SourceReference lists or raw records merely because their asset is selected. Never package input ZIPs or unfiltered source JSON in a cleaned bundle. Machine-readable records are newly constructed scoped records, not manufactured copies claimed to be original export JSON.

Original bytes remain unchanged. Their pixels, audio, embedded GPS/EXIF and intrinsic text may disclose context that cleaned generated metadata omits. Preview and receipt state this limitation. A rule's original-only exception does not release an untargeted layer, candidate or excluded occurrence; surviving uncertainty stays uncertainty. No claim removes a visual likeness or intrinsic metadata. Metadata stripping remains a separately disclosed derivative capability outside this slice.

Freeze exact original/layer source identity, not all file bodies in memory. Compute hashes from actual successful bounded reads. If original bytes are missing/unreadable, record no invented size/hash or byte-preservation verification. Whole-ZIP chain identity and original-document proof are not substituted for media SHA-256. Original preservation copying stays a separate explicitly approved action; this slice does not put those source files into readable output.

## Per-item receipts and partial output

Use a versioned local receipt bound to the plan and attempt. A planned target identifies its exact event/occurrence context record or physical original/layer/derivative payload; a shared physical target is one target with all permitted references retained. Freeze safe enum codes and labels, not arbitrary native exception messages or raw paths.

Distinguish these facts rather than one success boolean:

- Known missing physical bytes and unsupported requested transformations are previewed omissions, with no invented payload hash.
- A read failure, integrity/approved-size mismatch, renderer failure and sink refusal are different failures.
- A generated payload has measured bytes/hash, but is not yet a saved/verified output.
- A browser handoff is offered output, with unknown disk completion. A directory close is a successful local write acknowledgement. Reopening and hashing establish verified output separately.
- Cancellation, stale authority, not-attempted work and outcome-unknown handoff remain distinct. A stopped attempt never claims a complete catalogue or a retractable already-started download.

Return a structured receipt for every frozen target, emitted part and catalogue even when the writer stops. A fatal or partial attempt may offer a clearly labelled partial receipt. It must not call the approved full plan completed. Successful payloads retain actual hashes and part membership. No failed/missing/unsupported target acquires a fabricated successful payload entry. Progress reports actual read/write bytes and separately completed/failed/omitted/not-attempted items; estimated bytes remain explicitly estimated.

Keep the existing stop-on-original/sink failure policy initially. Composition omissions can preserve unchanged source components under the approved variant policy. Continuing other independent items after a read failure would require an explicit preview policy and a separately tested honest partial-catalogue contract; this proposal does not authorize silently changing the current stop behavior.

## Explicit narrow retry

Retry is an owner action after reviewing the failed-target receipt. Prepare the exact deduplicated failed physical/derivative targets and required still-permitted dependencies from the frozen plan. Do not rerun selection, expand context, rewrite successful outputs or use a new current query to modify the old plan. A failed derivative may reacquire already-written original/layer components only as explicitly listed dependencies, with the same source/hash authority and without writing duplicate successful payloads.

Eligibility requires unchanged full authority, policy, exact source identities/sizes, variant recipe and a failure known to precede a successful/unknown output handoff. Missing bytes, unsupported capability, integrity/source-size mismatch, changed evidence or stale authority require a new preview, not retry under old approval. A failed supported renderer may be retried only with the same recipe/capability and eligible source dependencies. A new codec/recipe or restored missing source is a new approved plan. A replacement session requires fresh validated preparation even when selected bytes happen to match.

Unknown sink outcomes are not retry-eligible until local output inspection reconciles their exact part/payload status. Browser download start alone cannot reconcile disk success. A known refusal before handoff can permit a fresh attempt; cancellation after handoff must preserve uncertainty. A failed volume may require all of its unsaved payload targets, explicitly listed, rather than pretending only the final asset failed.

Retry uses a fresh bounded writer and distinct safe attempt/part names. Never append to a broken ZIP writer or overwrite an unrelated saved file. Preserve already verified part identities and hashes. A resulting catalogue names every required prior and new part and distinguishes replaced failed/unknown attempts. If the application cannot establish a complete final part set, offer the narrow retry artifact and receipt as partial repair, not a complete readable collection. Do not add automatic persistence, automatic retry, background resume or paid/external calls.

## Independently reopened bundle verification

Reselect actual saved catalogue/parts or use the owner-granted directory. Read each part with finite limits; validate manifest/schema/path uniqueness and enumerate actual payload entries, not only the manifest's own declarations. Require every declared payload exactly once, correct part membership, byte count and SHA-256, all required parts, and no unexpected source ZIP/raw JSON or active external references in generated readable content. Preserved attachment bytes are opaque source components, not executable readable pages. Duplicate/conflicting paths, missing parts, extra payloads, traversal and mismatched hashes fail explicitly. The manifest cannot checksum itself; compare the saved catalogue against an external expected receipt hash when available and state the verification scope honestly.

Reconcile per-target receipt status from saved bytes. Verify original media against independently expected source bytes/hashes under the approved plan, derivative inputs/recipe/version against preserved permitted layers, exact historical context/uncertainty and local relative links. Independent test enumerations supply expected IDs/paths/counts/pixels. A writer-generated manifest cannot serve as its own complete expected oracle.

A verified bundle has intact declared bytes and scope agreement with its retained approved plan. Hashes are not proof of authorship or cryptographic authenticity. With no expected plan/receipt, report internal integrity only; do not claim current archive scope, exclusion correctness or restore authority. Inspect untrusted metadata/records inertly. Verification never executes selected HTML, source scripts, arbitrary URLs or source records. Automated offline browser checks open only the known-generated, independently verified test output.

Bundle evidence has its own scope and source identity. Only documents/files actually present and read in the saved bundle acquire measured bundle byte/hash proof. A retained original-document digest or locator is declared original provenance when that full document is absent; it is not a newly verified original SHA or an available source lookup. Opening an absent original source reports unavailable. Excluded or unfiltered original documents are not added merely to make provenance inspectable. Bundle records may provide measured, separately labelled bundle-context evidence without claiming they are original Snapchat rows.

Do not cast a manifest or these new context records into complete original Snapchat `QueryEvidence`, reuse an archive fingerprint claim as attestation, or transfer choices through bare matching IDs. A future in-product bundle reader requires an explicitly frozen versioned self-describing bundle format, bundle-specific authority and supported reopen adapter with independent literal fixtures. That product/format decision belongs in preflight; no guessed export variant or alternate matcher is authorized here. Actual offline readable context/composition round-trip remains required even if in-product bundle ingestion stays unavailable.

Actual round-trip tests save every browser part, extract all into one clean directory, open `index.html` via file:// and traverse conversation/media/context/manifest links. A matching HTTP preview alone does not establish offline portability. Reopening must work without the website, account, blob URLs, third-party scripts, missing folders or external requests.

## Bounded complete-bundle and cancellation evidence

Reuse sequential exact source reads, the existing 64 MiB item bound, default 128 MiB part target, 256 MiB part ceiling and backpressure. One emitted browser ZIP URL remains active at most; original/layer/composition budgets and originating cleanup retain EXPORT-02/MEDIA limits. Do not retain all emitted blobs. Metadata payloads, transcript windows, record serialization, manifest/receipt entries and in-flight transport need finite byte/item limits before implementation; a bounded ZIP part alone does not bound a full-history JSON string or catalogue.

Freeze measured chunk/page budgets during preflight. An initial proposal is at most 60 events per readable thread page, 50 occurrences per context page and 1 MiB serialized record chunks. These are untested starting limits, not heap/performance guarantees. They must preserve all permitted records and exact links through a bounded catalogue/index, or fail honestly rather than truncate. Reuse PERFORMANCE's accepted indexed/paged projection and ordering contract when available; do not add an export-side sorter or matcher. Catalogue partitioning, if necessary, needs a concrete root/index/checksum contract before code.

Run a generated actual multipart raw archive above two GiB through import, complete preview and the real local writer/sink on recorded desktop browser/hardware. Use distinct legitimate payloads/markers plus legitimate tiny composition/media/context fixtures; relabelled text or one repeated in-memory buffer is insufficient as sole raw-import/browser evidence. Preserve separate historical references even if physical source bytes are identical. Record input size, selected IDs/bytes, emitted parts, checksum/reopen results, processing time, accountable buffer/URL/reader/renderer peaks and available browser/process memory measurement. Name sampling/native-memory limitations. No headless/Node observation is promoted to a representative physical-desktop guarantee.

Cancel during active read, rendering, part creation, directory write and browser handoff; refuse a sink, simulate insufficient space/interruption and replace authority. Stop further work, release each acquired resource once and preserve source bytes. A native operation ignoring abort retains its real budget until settlement and cannot publish late output. Record control-feedback and stop/cleanup latency separately from completed export time. Above-item-limit originals and unmeasured browser codecs remain explicit unavailable paths; multi-gigabyte output does not establish support for one multi-gigabyte item.

## Literal acceptance and delivery loops

1. A complete tiny raw archive with three event slots referencing original A, one Memories save of A, a second original B, an ambiguous D/F reference, a missing metadata record, one exact layer LA and unrelated orphan LO yields handwritten context counts and the one canonical effective physical population. Complete and curated modes agree with the appropriate frozen QUERY projection, never an export matcher.
2. Exclude one A context and give it unique caption/location/title/name/proof canaries. Exclude F and protect shared LA through baseline rules. Serialize/scan every generated payload, path and receipt: these contextual/candidate/layer canaries are absent while independently permitted A context remains. Original intrinsic metadata disclosure remains explicit. A rejected baseline candidate still protected by a rule cannot leak through export.
3. Ordinary independent inventory D/F has no ambiguous historical date/recipient/inline claim. Surviving candidate states, owner versus export confirmation, repeated slots, missing/unsupported records, exact time/precision and coverage units remain distinct in records/pages/receipt.
4. Plain, zero-byte, duplicated-path original/layer bytes use the exact ordinal and match independent expected SHA-256. Missing/unreadable originals have no attested output hash. Every saved declared payload and volume matches actual bytes; no unexpected payload or external reference survives.
5. A supported same-canvas JPEG/PNG derivative matches independently expected full-size pixels and preserved source hashes. Unsupported nested transform, mismatch, animated source, video and missing layer produce distinct omissions with unchanged permitted components. No new faithful video/codec claim.
6. Fail exact target B before handoff after a verified A part. Receipt records A's actual part/hash, B's read failure and remaining not-attempted targets. Explicit same-authority retry reads only B and required allowed dependencies. Changed authority, source-size mismatch, unknown handoff or unsupported recipe refuses with no read/sink call. Complete repair is claimed only after the final exact part set is reopened.
7. Refused sink, canceled active handoff, disk-close failure and stale result produce distinct receipt states, once-only cleanup and no complete success. An outcome-unknown part is reconciled before retry; it is never blindly downloaded again.
8. Save and independently extract/reopen clean multipart context and composition bundles via file://. Every expected conversation/context/media link resolves locally, original bytes/derivative pixels and manifest inventories agree, all required parts are named, and excluded canaries/external requests/page errors remain absent.
9. Large actual raw import/export records honest scale/resource/cancel measurements. Chunked metadata preserves literal beginning/middle/end markers and all counts without whole-history serialization or retained emitted blobs. Missing/extra/duplicate/tampered parts fail verification.
10. Original sources remain unchanged after every failure/retry/reopen. No receipt, bundle or source digest is transmitted, automatically stored, used to restore review authority or exposed in public telemetry.

Author serial slices through public preparation/writer/verifier/adapter seams: scoped canonical snapshot; structured receipt/failure transitions; narrow retry; independent reopen/context/composition; bounded metadata/actual scale. For each slice use handwritten expected evidence, red-to-green tests, independent original-spec/standards review, distinct fixes and reviewer recheck. Shared export/MEDIA/FILTER file ownership must transfer before edits; no concurrent normalizer/store/resource mutations.

Run affected units, full existing units, build and unchanged plus new actual-import browsers at the appropriate freeze. Design acceptance supplies no private archive, provider, transfer or runtime verification evidence. Google/Immich authorization/transfers, original-metadata stripping, faithful composed video/new codecs, above-limit single-file streaming, full performance/hardware coverage and release remain explicitly separate gates.
