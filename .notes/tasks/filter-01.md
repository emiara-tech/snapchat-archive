# FILTER-01: Shared workspace query and portable state

Accepted design contract, 2026-10-08, after experience author, foundation independent review, workspace distinct correction and foundation recheck. [Design acceptance](../reviews/filter-01-design.md) closes F1–F3. QUERY and OCC code acceptance and final bounded interface/file ownership remain implementation prerequisites. This record accepts no runtime integration or completed phase.

## Value and requirements

A person chooses a period, source or phrase once and sees the same permitted evidence in every room. Removing one filter does not undo an exclusion. Restoring a private review file either installs its complete valid state or leaves the current workspace alone. Equivalent filter input does not discard a useful preview or restart an expensive profile.

The originating contract is [Phase 5](../specs/phase-5.md), especially criteria 1–4 and 6–10, with phase 2 identity/time facts, phase 3 associations/resources and phase 6 preservation. The accepted [QUERY-01](query-01.md) and independent [literal query oracle](query-01-oracle.md) control predicate, inheritance, exclusion, candidate, diagnostic and ordering behavior. FILTER-01 integrates those rules; it cannot redefine them.

## Prerequisites and bounded scope

QUERY-01 must pass its author, independent reviewer, distinct fixer and recheck loop. OCCURRENCE-01 must then supply complete versioned runtime evidence through actual local imports, original-byte copy proof, exact times, proven membership, physical entry identities and typed association proof. Its proposed `ArchiveDataset.queryEvidence: QueryEvidence | null` and explicit unavailable reason are the sole capability source. Use its pure `prepareQueryEvidence(dataset, associationDecisions)` operation to prepare typed owner choices before QUERY-01 selection. Bind to the final independently accepted OCC contract; a flat legacy dataset cannot be cast or reconstructed from accumulated asset dates into this capability.

Pure adapter/restore tests may start against complete hand-authored inputs. Runtime activation and browser acceptance depend on OCCURRENCE-01. Keep the current product intact until that dependency is accepted. After activation, incomplete evidence produces a truthful capability error, never an approximate collection. Do not publish an intermediate mixture of old and new selection rules across rooms.

Rule restoration has a separate local prerequisite. FILTER-01 can initially support query/item/association portability and reject unsupported rule state. Positive rule-state restoration requires the accepted RULES-01 implementation and its concrete deterministic validator/derivation operation. Do not claim that branch complete from a stub or implement participant expansion here to bypass the dependency. This is unfinished local engineering, not an external account/service gate.

This task covers query intent, atomic workspace state transitions, strict portable state, existing proposal integration, shared controls/counts, scoped consumer adapters and resource cleanup. It does not implement a new Guide grammar, a participant-rule framework, compatible-target migration by similarity, automatic browser persistence, paid inference, a public demo or VISUAL-001.

## One application interface

Use the existing workspace store as the Vue adapter. It exposes one canonical query, one collection result, a current revision/session stamp and existing domain commands. Application behavior lives outside pages and Pinia-specific reactivity. The query module still owns all matching and exclusion rules.

The workspace retains `setQuery(patch)`, `resetQuery()`, `exportReviewState()` and `restoreReviewState(text)`. Add an explicitly named full-query replacement operation for restore and prepared Guide actions. Equivalent names are acceptable; patch and replacement must remain separate operations. Existing review/association/undo commands keep explicit typed targets and frozen proposals.

A pure application module may prepare query changes and whole restore transactions, then return a complete next snapshot or safe errors. The store commits a prepared aggregate snapshot once. It must not assign decisions, query, associations, revisions and selection through sequential externally visible ref updates. Expected failures leave the old aggregate, history, previews and leases intact. Do not create a second store, a generic state framework, matcher callbacks, plugin ports or a command language.

The aggregate carries canonical query, item/occurrence decisions, owner association decisions, supported versioned rule definitions/exceptions and their deterministically derived effect, matched/effective collection and revisions. Derived deny targets are QUERY inputs, never a separately writable or imported source of authority. Without an accepted RULES capability, the aggregate has no rule definitions/exceptions and no rule-derived denies. FILTER-01 creates V2 owner-decision records only on an explicit existing confirm/reject action. Each has a durable local decision ID, exact occurrence/reference and candidate targets, action, timestamp and stable base evidence revision. Query changes never regenerate that ID; save, restore and undo/redo preserve it. The OCC preparation operation validates and projects these records without modifying baseline export proof. Session/reader ownership remains separate browser I/O. Rule authoring and exceptions belong to [RULES-01](rules-01.md); FILTER calls that module when supported and does not implement its policy in the store or pages.

Expose `matched` deliberately for review and `effective` for ordinary Library context, Conversations, Observatory, export, profiles and Guide evidence. Compatibility getters may project these results, but cannot rerun legacy filters, infer links or attach accumulated media history. `reviewOnlyDiagnostics` is available only for deliberate diagnostic inspection, never an ordinary payload or count. Raw immutable evidence remains behind explicit source inspection. Consumer adapters return permitted context fields and their exact proof, rather than passing entire dataset lookup tables into jobs or ordinary payloads. Archive-wide coverage remains separately labelled aggregate capability information; it never supplies unowned diagnostic source references or historical claims. Preserve exact query time and output ordering alongside formatted display dates. A consumer cannot sort/filter again using rounded legacy timestamps or a physical file's accumulated date.

## Permitted titles and names

Selecting a conversation or participant ID does not permit every retained field on its aggregate domain object. Ordinary projections of conversation titles and participant display names require proof for that exact value. Use a value recorded in a permitted selected row, or independently permitted identity metadata with its own exact target/source proof. A source reference must support the whole field value and identify its conversation/participant target. Merely sharing an entity ID or appearing in the dataset's accumulated label history is insufficient.

The bounded producer/application contract supplies the chosen title/name with its supporting source references. Reuse existing row/source facts where they can prove that field. If a value lacks permitted proof, return the neutral labels `Conversation` or `Participant`, with no claimed source reference. Do not derive the fallback from an unselected raw row, filename, private ID or accumulated label. If several permitted values conflict, use the accepted scoped occurrence/event order and a stable lexical source-ID tie order, not ZIP selection order. Keep only the chosen value's supporting references. This is a projection for these fields, not a generic field-provenance system or a second parser.

Permitted row scope includes effective selected occurrence evidence and its proven parent context, even when that parent event fails an event-specific kind facet. An effective image occurrence of a text event may therefore carry that row's proven title/author label without adding the text event to selected event IDs. Parent event/occurrence/file exclusions and explicit deny authority still dominate. Other rows sharing the parent conversation do not acquire permission. Independently permitted identity metadata must remain supported separately from those denied or unselected rows.

Every ordinary room, option label, worker, profile contribution, observation and export adapter consumes this field-level projection. Do not rebuild titles/names from retained conversation/participant objects downstream. Deliberate source inspection may expose its explicitly opened original row, including an excluded row; that is separate from ordinary context permission.

## Query patch and replacement intent

A patch changes only supplied facets. Absent fields preserve the current facet. A supplied undefined or malformed value is an error; supported neutral values clear the addressed facet. Replace each addressed scalar/plural facet before normalizing the whole candidate query. Passing a spread of the old plural query plus a new scalar directly to the full-query normalizer would incorrectly retain or conflict with the old facet.

Legacy scalar patches replace their corresponding plural sets: `year`, `participantId`, `conversationId`, `kind`, `review`, and `linkState`. For example, from years `[2019,2020]`, `{year:2021}` produces `[2021]` and `{year:null}` produces `[]`, preserving every other facet. A plural patch replaces that whole set. Range patches replace the whole range value, not an implicit merge of its bounds.

If the same patch supplies both scalar and plural forms, follow QUERY-01's explicit conflict rules within that patch: disagreeing nonneutral forms fail; a neutral scalar does not erase a supplied plural. Thus `{year:null,years:[2020]}` chooses `[2020]`. No object key order decides intent. Controls normally send one form.

`replaceQuery(input)` treats its input as one full query and applies QUERY-01 defaults for omitted accepted facets. It never merges omissions with current state. Restore and a frozen Guide proposal use this operation. Unsupported fields/versions, unknown IDs, malformed Unicode, invalid ranges or unsupported timezones fail without broadening the collection.

After normalization, compare canonical query values, not raw input or current matched IDs. Reordered/deduplicated sets, equivalent literals and timezone aliases do not change the query revision. A distinct valid query increments it exactly once, even if it currently matches the same IDs. A failed change increments nothing. Reset of an already-default query is a no-op. Every accepted change exposes one coherent query/collection/stamp.

## Revisions, proposals and profile state

The stamp identifies the current import session, attested fingerprint, normalization/occurrence versions, source evidence revision, effective dataset revision, query revision and review revision. The session component is not persisted. Reset/replacement advances it even when the same bytes are reselected and counters restart. A stale callback cannot become current merely because saved counter values happen to match.

Query/review counters belong to the application adapter. QUERY-01 only receives and echoes them. Source evidence revision used to validate owner confirmation is distinct from mutable query/review counters. A portable file cannot create authority by supplying old counter values. Restoration computes fresh runtime revisions from actual committed changes.

Preserve SCOPE-02's frozen Guide/profile proposal behavior: exact typed targets, current collection stamp, profile evidence/editor/style stamps, one-use Apply, cancel without mutation and stale rejection. Equivalent query input leaves a current proposal current. A real query, review, association, import, profile-year, editor or style change invalidates the relevant proposal. Never recalculate and expand target IDs in a page when Apply is clicked.

The Guide's existing local parser prepares a validated canonical preview through the same patch adapter and obtains evidence from the same effective result. Applying its frozen query uses full replacement with its expected stamp. Existing review actions expose their event/occurrence/media target kinds and scope; do not silently convert a file decision to an appearance decision or the reverse. Unsupported mapping fails honestly pending the appropriate curation task. Views render the prepared preview; they do not run their own exclusion loops.

Year profiles use effective events and the canonical timezone. Keep proven-owner, quote/copy, adequacy, packet and profile-only edit rules in their existing domain modules. A single explicitly selected shared year governs the profile. For several selected shared years, require an explicit profile-local year choice within that set. Choosing it changes only profile draft/year authority and the smaller measured owner population. It preserves the canonical shared years, shared collection, dataset/query/review revisions and Guide query/curation authority. It does not call the scalar workspace year patch. Profile topic proposals/jobs from the prior local year become stale through their profile authority.

Provide a distinct, explicitly labelled action to change shared years through the normal shared patch interface. That action changes the canonical year set once and invalidates affected collection consumers. Do not make an ordinary profile-year control perform both operations. With no shared year constraint, an explicit profile-local choice may select a usable permitted owner-text year. With neither constraint nor choice, the existing shared eligibility helper may choose the earliest usable year, never the current year by invention. If a later shared change leaves a local choice outside its allowed set or without eligible evidence, report that state and require a new choice where necessary; do not silently broaden the shared query. When no eligible owner-text year exists, keep the profile empty with an explicit explanation.

Bind navigation drafts to imported evidence, the profile-local year and canonical timezone. Source inspection and Back preserve the matching local year, draft, style and suspension without converting a shared OR set into a scalar year. A timezone change invalidates calculation/packets/topics and cannot apply another timezone's topic IDs. Dataset reset/replacement clears drafts. No-op filters do not restart profile jobs. Collection input counts and the smaller owner/profile-year measurements have distinct labels.

Every asynchronous observation, thumbnail, profile, export preparation and file-read completion captures the stamp. After a real commit or session replacement, obsolete work aborts and late results are rejected before publication. Failed restore and no-op query preparation do not invalidate current work.

## Portable state and atomic restore

Keep persistence explicit. This slice supports local state download and file restore; it adds no automatic localStorage writes. The file is private because query literals, IDs, decisions and fingerprints can reveal history. Do not include archive bytes, raw rows, excerpts, profile measurements/drafts, object URLs, physical reader handles, credentials or provider connection state. Literal query text remains private user input; do not claim arbitrary search phrases are secret-free.

Use a documented new portable schema version for canonical queries and typed targets. The envelope includes attested dataset fingerprint, normalization/occurrence identity versions, query/matching versions, stable evidence revision, complete canonical query, typed decisions and supported owner association decisions. Owner confirmations have a durable decision ID, exact target/evidence revision and source proof reconstructed from matching current evidence. Do not promote English link basis, timestamps, filename similarity or a legacy boolean into confirmation proof.

Rule portability is capability-aware. Until an independently accepted RULES module/schema is available, any rule or exception field/state rejects the whole file, even if its targets are otherwise known. An arbitrary top-level deny list is never persistent authority. Do not ignore unknown rule fields, drop unsupported rules or downgrade current nonempty rule state through a file that cannot represent it. Once supported, the envelope carries the complete supported versioned rule/exception state, including an explicit empty state when none is active. Bind its shape to RULES-01 rather than accepting a permissive object or implementing another rule engine here.

With that capability, FILTER invokes the RULES deterministic validation/derivation operation using immutable baseline exported resolved/possible associations, scoped membership/participation facts, validated restored association/review state and exact supported physical exceptions. Fingerprint, evidence version/revision and target roles must agree. Current owner rejection cannot erase baseline protection. An exception releases only the exact original/layer target for its named rule, never event/occurrence permission, another rule's blocker or an explicit item exclusion. Derive typed deny targets, blocking reasons and effect counts before QUERY selection.

Supplied derived targets/effects/counts are optional consistency evidence only; if present, all must exactly agree with the derivation or restoration rejects. They cannot replace the rule definition or confer authority. This validates a private file's consistency, not its cryptographic authorship; restoration remains an explicit owner action. Serialized proposals and imported counters never create apply authority. If a later schema permits serialized history, its effects must be validated against each recorded before/after state and scope, not just today's final state.

Restore performs these steps before any commit:

1. Bound encoded input to the existing 10 MiB limit. Browser file-size checks occur before reading; pure validation also bounds supplied text. Parse failures return fixed safe codes/paths without native JSON excerpts.
2. Validate the entire envelope, supported version and attested fingerprint/normalization/identity compatibility. Unverified evidence cannot authorize restoration.
3. Normalize the complete saved query through the accepted full-query contract, not scalar patch intent. Validate every typed decision target, status, timestamp and association proof/reference. Reject unknown fields, unsupported rule capability/state and bare deny authority. No unknown target is silently dropped, and no invalid facet becomes a neutral default.
4. Validate association exclusivity, physical availability and current source proof. Preserve owner confirmation separately from export proof. Where supported, invoke RULES validation/derivation against the immutable baseline and validated proposed state. Reject invalid exceptions or any supplied derived target/reason/count that disagrees with the complete deterministic result. Do not commit associations or rule state first.
5. Prepare the complete matched/effective collection through QUERY-01 using only validated choices and freshly derived deny targets, then determine actual query/review changes. Check the captured current stamp again if file reading/preparation was asynchronous.
6. Publish the complete next snapshot once, then invalidate obsolete jobs/proposals/leases. Identical complete state is a no-op. Nonidentical restore is one undoable transaction, not one history entry per target.

An exact same-evidence multipart reimport in a different selection order restores logical targets, resolving media through the new session's exact physical entry IDs. Saved source selection order, blob URLs and old source-reader IDs are not playback instructions.

Every currently exported v1 file carrying normalization version 4 must reject before any mutation at the new normalization-5 boundary. This slice does not implement a proven compatible-target migration, so unchanged-looking IDs cannot authorize one. QUERY-01 scalar full-input compatibility remains usable for explicit query replacement and its tests; it is not permission to migrate old portable decisions. A normalization correction that changed previously conflated IDs requires a visible incompatibility report. Any future compatible migration must prove exact source/target identity, reject namespace ambiguity, preserve whole-query intent and require renewed confirmation where owner proof is absent.

Different evidence, unsupported versions, ambiguous migration or missing proof return a visible mismatch/needs-review report and apply nothing. Offer opening matching ZIPs or retaining the current workspace. A future compatible-target import needs a separately reviewed exact target preview and explicit Apply; similarity-based or automatic partial restoration is outside FILTER-01. Rejecting the whole file is preferable to silently importing only its apparently valid portion.

A successful restore can be undone as one clearly labelled whole-state transaction, including its query. Ordinary item-review undo keeps current filters; do not accidentally change that existing intent by storing every query change as a review action. Redo restores the exact validated state, and a new review transaction clears the redo branch. History and revisions remain unchanged after invalid restore. Download/storage errors leave temporary state usable.

## Shared controls, counts and navigation

Every required canonical facet is operable in the existing desktop filter component: year sets, participant/conversation sets, kind sets, origin sections, literal text, review/link sets, timezone, one calendar/instant range and unavailable-time policy. Use labelled controls and existing styling. No visual redesign is part of this task.

Show removable active chips. Removing one member preserves other members and every other facet. Clearing a reviews chip returns active statuses, not the empty set that QUERY-01 interprets as all four statuses. Timezone reset explicitly returns UTC. Range removal removes only the range. A clear-all action restores the documented canonical defaults and never changes review decisions or deny authority.

Show the chosen timezone beside date/year/range controls and shared summaries. Compute year options through QUERY-01 from an ephemeral option query that clears only the canonical `years` facet. Preserve participant/conversation, kind/origin, literal text, review/link sets, range, unavailable-time policy and the exact canonical timezone. Use the same prepared evidence, validated choices and rule-derived deny authority as the shared collection. This calculation does not mutate the shared query, revisions, history, previews or leases. Do not clear other facets to fill the menu or implement a second matcher.

Derive numeric year options from the option result's effective selected event/occurrence instant facts in that zone. Offer only canonical years 1–9999. A supported UTC-limit instant with local astronomical year 0 or 10000 remains evidence but supplies no invalid year option. Calendar conversion must preserve era and compare numeric components under the corrected QUERY contract. Use exact signed microsecond calendar conversion with floor at negative boundaries, rather than the old UTC asset.year, a rounded legacy timestamp or unselected candidate/file history. Inventory/layers with no selected historical instant add no invented year. Date-only evidence does not supply an instant year option because QUERY-01's temporal year/range contract excludes it. A selected year remains a removable active chip even when the permitted option result has no evidence in that year; do not silently delete the user's constraint. This option scope permits broadening `[2019]` to `[2019,2020]` when permitted 2020 evidence satisfies every other retained facet.

Date-only records retain their known recorded date while stating that an instant is unavailable. Invalid, absent and unzoned evidence remain distinct. Never invent midnight or relabel a known date unknown.

Give counts concrete units. The shared summary distinguishes matched/effective events, historical appearances, physical original files and missing-media records. Candidate files, standalone inventory, layers, support resources and postponed reviews have their own available detail. Two copied source documents do not double a logical appearance. A candidate never counts as an inline attachment, recipient or appearance of that file.

A Library file card lists only its selected occurrences with their dates, captions/location and exact source references. It may say that several appearances share one file; it must not use a media object's accumulated history or excluded metadata as its default caption. Conversations use the scoped inline associations. Observatory measurements, evidence links and profile input come from the same effective collection. Export preparation consumes a frozen effective projection, exact physical resources and the canonical timezone.

Empty states explain the active constraints and offer targeted clearing actions, such as removing this year, literal or conversation. These are normal validated patches. They never undo exclusions or auto-clear filters. If explicit excluded review matches exist but effective counts are zero, distinguish review matches from the ordinary collection instead of calling the archive empty.

Navigation and source focus preserve the query. Focus outside the permitted selection cannot silently widen filters or open an ordinary media lease. Offer deliberate review/constraint-clearing controls where appropriate. Source-return room/selection and query state survive actual unmount/Back. Render private labels and literals inertly.

Complete export's documented clear-filter action uses the shared application command and shows the resulting query before approval; the page cannot make its own alternate selector. Existing original-ZIP preservation remains separately explicit and must not be confused with cleaned complete/curated scope.

## Original bytes, overlays and resource leases

Query changes, review, restoration and undo never rewrite source ZIPs or source documents. Ordinary resource access requires the current effective original/inventory/support membership and exact source ID/path/entry ordinal. Resolved supporting layers may bypass kind/time facets as QUERY-01 resources, but never exclusion authority. A denied layer clears composition/resource references without dropping an otherwise permitted base.

Browser media adapters own URL/buffer leases and reader lifetime. Replacement or a transition withholding a displayed resource closes it, aborts decode/composition work and rejects late attachment. A lease releases through its originating reader exactly once, including after replacement. Deliberate review access is distinct from ordinary effective access; a stale URL or route does not authorize a denied resource.

Preserve current composition byte/pixel limits, original-download fallback, unsupported-transform diagnostics and bounded thumbnail concurrency. Export adapters retain exact source-byte sizes, physical ordinal identity, safe composition and frozen plan checks. They receive only selected occurrence metadata and permitted proofs/resources, never reviewOnlyDiagnostics or full unfiltered source JSON. Candidate inventory may be exported as deliberately selected standalone bytes without claimed uncertain context.

## Numbered acceptance criteria

1. Patch tests prove replacement/clearing of each legacy scalar facet, plural replacement, mixed-form conflict rules, full range replacement and absent-field preservation. Full replacement defaults omissions independently of current state.
2. Canonically equivalent patches/replacements leave query revisions, current previews/jobs and history unchanged. A distinct query changes the revision once; invalid input changes nothing. Current matching ID equality alone never defines a no-op.
3. One aggregate commit exposes query, choices, association facts, collection and stamps coherently. A failed restore with an invalid final query field leaves every old choice, history entry, focus lease and preview intact.
4. Portable state round-trips its complete canonical query, typed choices and supported owner proof on the same attested evidence, including reordered multipart imports. Unsupported versions, altered fingerprints, ambiguous namespace targets, malformed proof or unknown exclusions apply nothing.
5. Normalization-4/v1 portable state rejects at the new version boundary with every old choice/query/history unchanged. Full legacy scalar query replacement follows accepted defaults without retaining old facets. No portable target or confirmation proof is invented from that syntax compatibility.
6. A successful nonidentical restore is one undo/redo transaction with exact prior query/choices. Saved counters never make an obsolete job current. Replacement during asynchronous file reading rejects the stale restore.
7. Every shared facet has accessible controls/chips. Removing one set member, clearing one range/text constraint and clearing all have exact independent effects; review exclusions remain in force. Targeted empty-state actions preserve all unrelated facets.
8. UTC/Europe/Oslo late-New-Year, spring/fall daylight-saving, signed -1 microsecond and exact half-open range fixtures display/return the accepted query results. Date-only/unzoned/invalid states retain their source meaning.
9. All room input adapters consume the identical effective event/occurrence/resource IDs and timezone for a given stamp. Review mode can show matched excluded records but ordinary observations, profiles, exports and scene evidence remain empty for those targets.
10. Frozen Guide/topic previews survive equivalent query input and reject real stale changes. Apply uses original typed targets once. Source Back preserves the correct profile-local year/timezone draft; profile measurements remain explicit subsets. A local profile-year choice preserves shared query/collection authority; a separate explicit shared-year action invalidates it normally.
11. Denied M3 caption/location/source canaries, candidate Q's exclusive proof canary and unowned diagnostic references are absent from every ordinary UI/worker/profile/export projection. Full immutable evidence remains available only for deliberate review.
12. Layer exclusion preserves its permitted base, removes all ordinary support/composition references and releases its lease. Base/context exclusion never promotes a resolved layer into inventory. Repeated filtering/restoring/replacing produces no stale image, URL/buffer leak or unsupported composition claim.
13. Hashes of every original fixture ZIP, document and physical media/layer entry match before/after filter, review, restore and undo. Cleaned export manifests/HTML contain only permitted context and exact original resource bytes.
14. Invalid private-key/text/proof canaries never appear in safe errors, logs or public diagnostic fields. No search, query, choice, fingerprint, focus target or archive evidence is sent externally, including through analytics. No runtime test fixture route or production synthetic branch exists.
15. Conversation-title and participant-name values supported only by excluded or unselected rows, and their source pointers, are absent from ordinary room/worker/profile/export context even if the entity ID remains selected. A permitted row or independently permitted identity field can supply a proven value; otherwise the neutral fallback has no invented proof. A selected image occurrence retains only its permitted parent-row fields while its text event fails the event-kind facet. Denying that parent withholds the occurrence and its fields.
16. From shared years `[2019,2020]`, choosing profile-local 2020 measures only permitted owner evidence in 2020 while query/review revisions, shared IDs, Guide authority and active shared filters stay unchanged. Profile-only authority updates, old profile proposals fail, and Source Back preserves local 2020 and edits. The separate shared-year action can replace the shared set with `[2020]` once, with normal collection invalidation.
17. Unsupported/unknown rule state and bare deny lists fail restoration before mutation. With supported RULES, a missing protected target, inserted unrelated valid target, altered unproven physical exception or falsified derived count rejects the whole file. A valid rule restore derives its denies/reasons/effects through RULES before QUERY selection and commits one undoable complete snapshot. Failed cases preserve query, choices, associations, rules, history, stamps, proposals, jobs and leases.
18. Year-option computation clears only the years facet through QUERY-01. It preserves all other constraints, authority and timezone, returns only permitted instant-backed years and changes no shared state. An active `[2019]` set can offer permitted 2020 for addition; denied 2023 or unrelated conversation 2021 does not enter the options. Signed negative instants and zone boundaries use the exact accepted calendar facts. Selected years with no current option remain removable chips.
