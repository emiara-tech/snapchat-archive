# MEDIA-02: Local mixed media and occurrence navigation

Accepted design contract, 2026-10-08, after experience author, workspace independent review, root distinct correction and workspace recheck. [Design acceptance](../reviews/media-02-design.md) closes M-D1/M-D2. Prerequisites, final interfaces and assigned file ownership must freeze before implementation. Admission limits still require independent measurements before code acceptance.

## User outcome and originating requirements

An owner can open a recorded photo, sticker, animation, audio clip or video, follow its exact historical uses, and save the unchanged original. One failed preview does not remove the message or make the whole exchange unusable. Uncertain candidates remain understandable without becoming invented attachments or recipients.

Original [Phase 3](../specs/phase-3.md) P3-01 through P3-12 remain binding. Phase 4 criteria 1, 4, 5, 6, 8, 9 and 10 govern mixed-media threads, focused viewers, navigation and privacy. Phase 6 criteria 2 through 6 govern scoped context, unchanged original bytes, safe filenames and honest image/video composition claims. This bounded task cannot close every criterion or the complete phases.

Use the accepted [QUERY-01](query-01.md) and [query oracle](query-01-oracle.md) for selection, typed targets, link states, exact time, scoped proof and exclusion. [OCCURRENCE-01](occurrence-01.md) supplies original-byte proof and distinct historical uses. [COVERAGE-01](coverage-01.md) supplies limitation/population semantics. [RULES-01](rules-01.md) controls shared original/layer withholding and explicit exceptions. [FILTER-01](filter-01.md) supplies the canonical workspace transaction, session/revision authority and portable-state boundary. Bind to its independently accepted contract before integration.

## Current baseline and practical prerequisites

`src/components/LocalAsset.vue` renders local images, video and audio, offers unsupported attachments as downloads, and has a bounded full-size same-canvas PNG composition path. It owns reader acquisition, source inspection, local fetches, composition controllers and release inside the component. Its optional asset ID/path fallback does not form an authority-checked application interface.

`src/lib/imageComposition.ts` guards static JPEG/PNG source bytes and dimensions before native decode. GIF and animated PNG do not pass that static guard. Each composition input is limited to 16 MiB, 8192 pixels per edge and 12 multiplied by 1024 squared pixels. Unknown/nested recorded overlay transforms remain unsupported. Those checks and the versioned recipe are established local boundaries; their existence does not establish animated or composed-video support.

`src/lib/localThumbnail.ts` bounds thumbnail outputs to a 384-pixel edge, source bytes to 32 MiB and shared native decoders to three. Native decodes still finishing after abort retain their slot until settlement. The Library and conversation cards currently use LocalAsset directly rather than consistently using this bounded thumbnail path.

`LibraryView.vue` derives file context from event asset IDs and accumulated physical-asset dates. `ConversationsView.vue` derives attachments/candidates in the page and passes physical kinds to LocalAsset. OCCURRENCE-01 must preserve each declared kind, caption, location, time, reference slot and proof before this information is lost. MEDIA-02 must consume that scoped projection rather than reconstructing it from the old flat dataset.

The existing browser download implementation is `downloadLocalBlob`/`downloadBundlePart` in `src/lib/exportBundle.ts`, covered by `tests/browserDownload.test.ts`. It releases one owned URL after refusal, cancellation or its bounded handoff interval. A browser download start is not proof of a completed disk write. Reuse this boundary instead of introducing another download framework.

`SnapchatArchiveReader.readMediaEntry` currently reads a whole local entry and creates a URL. Its MIME mapping recognizes only JPEG, PNG and MP4. Domain metadata recognizes additional kinds, which does not prove playback. A focused reader change must carry operation cancellation and a finite byte limit into the existing exact-entry read, preserve integrity/actual-size checks, and return a lease tied to its originating reader. OCC's reader-signal work must freeze first so two owners do not edit that boundary concurrently.

Pure media application tests may use complete hand-authored QUERY evidence. Real room activation requires accepted QUERY/OCC/FILTER integration. Missing capability stays unavailable. The producer currently has exact, ambiguous and unlinked rules; no new time-proximity inference or export variant is authorized here. Test the inferred-state application contract with independent typed evidence. Imported inferred-state acceptance remains open until a source-backed producer rule and raw fixture are separately accepted.

## Small application and browser interfaces

Keep domain/context/navigation behavior outside views and resource I/O outside the pure application module. Use the existing application/workspace snapshot and exact entity IDs; do not create another archive model, media registry, matcher, callback language or provider layer.

The proposed public application operations are:

```ts
prepareMediaView(snapshot, intent)
  -> prepared focused view and bounded context page | safe typed failure

prepareMediaNavigation(snapshot, target)
  -> exact permitted navigation intent | blocked/unknown/stale result
```

An intent targets an event/reference occurrence or physical media ID, carries the expected current authority, and distinguishes ordinary effective access from deliberately entered review. Its page cursor belongs to that exact dataset/evidence/query/review/session authority, target and access scope. Agree on final field names against the accepted application types; no saved cursor or route establishes authority by itself.

The prepared result contains version/stamp, exact focus target, scoped displayed kind/time/precision, permitted caption/location, confirmed attachments, uncertain candidates, unlinked/missing records, independently bounded occurrence contexts, typed source/navigation targets, limitations and exact original/layer read requests. It never contains raw history, whole source documents, archive-wide participant lookup tables, blob URLs or expiring reader handles. Context pages contain at most 50 occurrences and retain stable exact ordering with a cursor for the remainder. Equal media IDs do not collapse separate reference slots or events.

The browser adapter exposes acquisition and original-download operations for these prepared requests. It verifies current authority and exact source/path/entry ordinal before starting the read and again before publishing a lease, native source or download. A request identifies its physical role, access purpose and current permitted relationship. A bare path, asset ID, remote URL or boolean `review` prop cannot bypass validation. Browser/reader/native-media objects remain behind this adapter; LocalAsset and pages render its state and dispatch existing actions.

A lease has a bounded local source, capability/state, an operation cancellation owner and idempotent release through its originating reader. A thumbnail, focused original, layer, composed derivative and download each have explicit ownership. Do not combine unrelated cleanup into an unconditional revoke against the current reader. Repeated release is safe, and a late acquired lease that has lost authority is immediately released without attachment.

## Evidence and navigation behavior

Confirmed inline associations come only from the current effective collection's typed confirmed relationships. Export-exact and owner-confirmed proof remain distinct. The event-to-file result and file-to-occurrence result agree on each exact confirmed occurrence, even when one event references several files or one physical file appears repeatedly. File context uses each occurrence's own metadata and source proof, never an accumulated physical date/caption or all of a file's historical sources.

Inferred/ambiguous relationships appear in a separate candidate section with their scoped basis and remaining permitted candidate IDs. An explicit candidate preview can read only a candidate still authorized by that effective reference or deliberate review scope. Candidate preview/download never confirms the link, adds a recipient or turns its date into file history. Denied candidates and candidate-exclusive proof are removed before preparation. One surviving candidate remains uncertain. Confirm/reject/undo uses the accepted owner-decision application command with its exact occurrence/reference/candidate and evidence authority; views do not construct proof or mutate exported associations.

Unlinked occurrences retain their recorded reference and available kind/time/context. A known missing logical media record has metadata but no physical download. An available standalone original can be opened from authorized inventory without acquiring an invented conversation, period or recipient. Unknown references do not attach an unrelated inventory file. Rejected and baseline possible relationships remain available only in the explicit review/rule evidence scope authorized for them, not as ordinary contextual metadata.

Navigation targets specify conversation, event, occurrence/reference and media IDs where established, plus the current collection authority and an explicit return target. A Library occurrence opens that exact event and bounded neighboring text. The message-to-media viewer highlights the originating occurrence, and the reverse action returns to the same event. Memories occurrences open their save/source context without a conversation. Candidate navigation opens the reference's candidate review context, visibly uncertain.

A blocked target reports which current constraint or exclusion prevents ordinary access and offers an explicit existing FILTER/RULES action. It never broadens filters, removes a rule or switches to review automatically. Ordinary failure feedback does not expose denied labels, excerpts or proof references. Close/Back preserves shared query, room selection, thread window/scroll and keyboard focus after an actual unmount. Missing/stale return targets produce a safe room-level fallback rather than silently focusing a different event. Source inspection resolves the exact typed source target through the bounded COVERAGE/source adapter.

## Preview and failure states

Separate metadata presence, local-byte availability, read integrity, decoding capability and relationship certainty. The browser result uses fixed reason codes and safe labels for loading, ready, no physical bytes, unreadable/damaged entry, unsupported encoding, budget exceeded, canceled and stale. A metadata-only file is not an unsupported codec. A malformed codec is not proof that the file was absent. A failed decoder does not alter link proof, text, review choices or surrounding navigation. Retry addresses only the current exact resource and requires unchanged authority.

| Recorded content | Bounded presentation and fallback |
| --- | --- |
| Static image or static sticker | A safe local image preview when source inspection/native decode succeeds. Preserve the occurrence's sticker label while decoding its actual supported image encoding. Use a bounded thumbnail in a card and a focused original on demand. |
| GIF or supported animated sticker | A verified bounded poster by default and explicit Play/Stop animation. Reduced motion defaults to the poster. Native playback must be exercised with actual animated source bytes; a static PNG relabelled GIF does not count. M-D2 defines the first-frame poster and source attachment semantics. Animation is separate from static image composition. |
| Audio | Passive card metadata and an explicit open/play action. The focused viewer has labelled native playback/seek/volume controls when the browser decodes the actual local source. No autoplay or nested audio controls inside a card button. |
| Video | A bounded passive poster/metadata card and focused native playback with user initiation, correct aspect/orientation and accessible controls. Do not rewrite duration, frame sequence or audio. Metadata readiness is separate from successful frame/playback readiness. |
| Attachment/unknown/system-like record | Inert bounded metadata and an exact original download when bytes exist. Unknown types remain unknown. No iframe, embed, HTML/SVG document execution or remote resource preview. A recorded system-like unsupported row stays a record placeholder rather than becoming a fabricated message kind. |
| Missing original | Retain permitted occurrence/event metadata and source action. Explain absent bytes; do not offer an unavailable file download or fetch its old remote URL. |
| Unsupported or damaged codec | Retain permitted metadata, exact source and original download where bounded reads succeed. Use a clear decoder/read failure state and keep the thread usable. Never substitute a different file. |

Freeze a finite encoded-source and animation-inspection budget before implementing animated support. The proposed initial GIF limits are 16 MiB encoded bytes, the current 8192-edge and `MAX_COMPOSITION_PIXELS` logical-canvas ceilings, at most 256 frames and at most 48 multiplied by 1024 squared canvas pixels across those frames. These are explicit proposed admission limits, not proven browser heap bounds. Validate counts/dimensions safely before native attachment. Unsupported animation metadata or a failed bounded poster is an honest capability failure. Do not weaken static composition guards to make GIF pass. Confirm or revise these limits through independent synthetic measurements before code acceptance.

Cards do not start audio/video/animation or decode full originals eagerly. Reuse the 384-edge thumbnail and three-decoder shared budget. Keep a finite visible card lease budget, proposed 24 concurrently owned card thumbnails, with placeholders/paging for additional media slots. The thread's existing 60-event window does not authorize unbounded attachments within one event. Preserve all occurrence counts and offer bounded media/context paging. Native decodes still finishing after abort occupy their budget until settlement; late bitmaps/canvases are closed. Focused playback owns at most one audio/video element per viewer and pauses/detaches it when closed or withheld. Measure focused-image/composition coexistence rather than claiming an unmeasured total heap bound.

## M-D1: Per-purpose admission and readiness policy

These initial finite limits are design admission policy. Independent synthetic measurements may require an explicitly reviewed revision before code acceptance; they are not a claim about total browser/native heap. The exact-entry adapter checks advertised size before reading and actual output during decompression. A false advertised size cannot bypass the actual limit. Timeouts use the operation's monotonic elapsed clock and fixed safe reason code `readiness-timeout`, never an arbitrary native error excerpt.

| Purpose | Encoded source ceiling | Decoded/admission ceiling | Ownership and readiness |
| --- | --- | --- | --- |
| Static card thumbnail | 32 MiB | Existing 8192-edge/12 multiplied by 1024 squared pixel source inspection; output edge 384 | One shared card pipeline permit before read, held through decode and encoding. |
| Focused static image/sticker and static composition input | 16 MiB per original/layer | Existing 8192-edge/12 multiplied by 1024 squared pixels; existing supported static guards and recipe | At most two foreground encoded-input leases and two foreground static-native jobs. At most one separately owned composed output/derivative. |
| GIF inspection, poster and focused Play | 16 MiB | Logical canvas at most 8192 per edge and 12 multiplied by 1024 squared pixels; at most 256 frames; canvas pixels multiplied by frame count at most 48 multiplied by 1024 squared; static poster edge 384 | Poster uses a shared card/native permit even when requested by the focused viewer. Live animation uses the sole focused playback source. |
| Video card poster | 32 MiB | After metadata, frame dimensions at most 8192 per edge and 12 multiplied by 1024 squared pixels; poster edge 384 | Shared card pipeline permit owns read, metadata, one first displayed frame and encoding. Card defaults to metadata until that bounded poster is requested. |
| Focused audio/video | 64 MiB | Video metadata dimension admission as above before requesting a ready frame or Play. Actual first-frame/playback readiness remains separate from metadata. Audio has no guessed image limit. | One focused native audio/video/animation playback source. No autoplay. Only explicit user playback; duration is not a loading timeout. |
| Unchanged-original download | 64 MiB | No decoder; exact final actual size/integrity and source hash | One foreground lease inside the same two-lease foreground pool; existing download sink owns its separate handoff URL. |

Across rooms, at most three shared card pipelines may acquire an encoded source or run native thumbnail/GIF/video-poster work simultaneously. Reuse the existing three-decoder scheduler by extending admission to occur before source acquisition. Do not add a separate three-slot queue per room. At most 24 visible card requests, including pending work and completed derivatives, are owned at once; there is no background queue of all media in the dataset. Every completed card derivative is at most 384 per edge and 2 MiB encoded. A derivative above that limit is discarded with an honest capability state. Originals used only for a card are released after the derivative is ready, except when a still-running native operation requires its bounded source until settlement.

The foreground pool owns at most two exact-entry reads or retained encoded original/layer/download sources. It is shared by the focused viewer, composition and original-download actions, so a download cannot create an uncounted third lease. Original and layer inspection use this pool rather than the card pipeline. At most one foreground composed derivative and its one output canvas may coexist with the two encoded inputs. Its canvas retains the established 12 multiplied by 1024 squared pixel/8192-edge guard and its encoded output has a 64 MiB ceiling checked before retaining or handing off the output. Its derivative URL has separate ownership/release and is not counted as an encoded-input lease. This explicitly permits original plus layer plus one composed-output URL without hiding a fourth source. Waiting for foreground capacity returns a safe busy/loading state and never disposes the currently useful source merely to hide over-allocation. Shared cards and foreground reads together have at most five simultaneous source-acquisition owners. Browser copying, native codec allocations and native retained frames are measured separately; these owner counts do not prove a total heap ceiling.

A queued request has at most ten seconds to obtain its permit. From permit admission, whole-entry acquisition, validation and first ready publication have a thirty-second total deadline. Inside that total, native image/GIF decode, video metadata, video first-frame/poster acquisition and derivative encoding each have a ten-second phase deadline. A subsequent explicit video seek has its own ten-second frame-readiness deadline. Normal audio/video/GIF playback after readiness has no imposed thirty-second duration cutoff. An unchanged-original download has a thirty-second acquisition/verification deadline, followed by the existing separately bounded browser handoff interval. The handoff interval does not establish disk completion.

Timeout removes a queued request or aborts the owned exact-entry read. Native audio/video/animation sources are paused and detached, and authority is invalidated before any late completion can publish. Close intermediate canvases/bitmaps and release URLs through their originating owner. A native promise that ignores abort retains its real scheduler slot and required encoded source until settlement; timeout cannot manufacture a replacement slot. A stalled exhausted pool returns an honest busy/unavailable state while text, Back and cancellation remain usable. Operation timeout never closes a still-current archive reader. Query no-ops preserve work; actual authority changes use the same cleanup.

A native video metadata check cannot promise that the browser made no internal allocation before the dimensions became known. Over-limit video dimensions prevent frame capture or Play publication and produce a download/metadata fallback. Observe native/source owner peaks and responsive cancellation in actual-import browser measurements before accepting support. Unsupported inspection or unavailable codec remains a capability failure, not a guessed successful poster.

## M-D2: Genuine static GIF poster and explicit playback

Initial animated support is bounded GIF source bytes, including a recorded animated sticker encoded as GIF. APNG and other animated encodings retain metadata and unchanged-original download but have no claimed bounded poster/animation capability in this task. Declared occurrence kind remains independent of inspected byte encoding.

The poster is a newly encoded static derivative of the GIF's first logical displayed frame on its logical canvas, including its declared background/transparency and the frame rectangle/offset. A poster decoder must establish that exact source frame within M-D1's limits without attaching the animated original to an image element. It does not seek to a later frame, pick an arbitrary native moment or substitute a stock/static image. The derivative owns a separate local lease, is labelled as a poster and is never labelled an unchanged original or faithful flattened animation. If the safe frame path is unavailable, retain metadata/source/download and an honest poster capability failure.

Only explicit focused Play attaches the already admitted unchanged GIF source to native animation. Cards, initial focused state and reduced-motion defaults contain only the static poster or metadata, with no attached animated native source. Stop, close, targeted withholding and authority replacement detach the animated source, revoke its owned source lease when safe and return to the same verified poster. Merely hiding an animated element is insufficient. A fresh Play may restart the unchanged native animation; this task does not claim frame-accurate Pause/resume or a rewritten frame scheduler. Static composition guards remain unchanged.

## Originals, download and safety

Every available permitted original kind has an explicit unchanged-original download, independent of preview success. Read the exact physical entry and verify its actual byte count/integrity before invoking the local download sink. Compare fixture outputs against independent source SHA-256 and bytes. Derive a platform-safe stable download filename and allowlisted extension/MIME from the validated resource, never from a raw remote URL or credential-bearing record field. Download unknown/active document formats as attachments; the application never renders them or navigates into a blob document. Saving unchanged bytes does not establish that opening that downloaded file elsewhere is safe.

Preserve the existing 64 MiB item ceiling for the bounded local download path and apply finite byte guards before copying/decompressing for preview, with actual-byte guards during reads. An image over the 16 MiB preview limit but within the 64 MiB download limit remains downloadable. An item above the download limit has an explicit capability message; source ZIP preservation and later streamed larger-file download are separate actions/gates. Do not offer a working-looking download that bypasses the guard or silently truncates bytes.

Downloads capture the same current authority and reject a change before start. Use a separately owned download lease so closing a viewer does not release the wrong source or retain every old URL. Refusal/cancellation releases owned resources. Once the browser handoff has started, cancellation reports that fact and does not promise to retract a disk download. Do not show disk completion from the current ten-second URL release interval. No original is converted, flattened, stripped or recompressed by this action. Warn that original pixels/embedded metadata may retain private context, as required by Phase 6 and RULES exceptions.

Archive strings remain inert. Remote media URLs, credentials, script-like attachment content and unsafe schemes never become fetch sources, native element URLs, download names or worker/telemetry payloads. The only local fetch sources are current adapter-owned blob leases. Errors expose safe codes/labels rather than source bytes, arbitrary input keys or native parser excerpts.

## Overlay behavior and cleanup

Only current resolved, permitted supporting-layer edges can support a composed view. Possible base/layer facts from OCC/RULES are byte-protection evidence and never a composition recipe. Missing bases, missing/unreadable layers, competing candidates, unknown transforms, timed/animated overlays and unsupported codecs remain distinct limitations. Offer exact original/layer downloads only under the appropriate effective or deliberate review authority.

Retain the existing verified same-canvas JPEG/PNG composition capability and shared versioned recipe for preview/export. Unsupported nested placement/rotation/timing remains separate. Explicit choices distinguish original, separately inspectable layer and composed PNG derivative. Initial media open defaults to original; the layer/composed mode cannot pretend to be byte-preserved original content. Derived download remains separately labelled with recipe/source hashes and metadata changes. Animated GIF/APNG/stickers are never frozen into a claimed faithful flattened original. Video remains original plus separately inspectable permitted sidecar; no static overlay, screenshot or CSS stack establishes a faithful composed-video output.

Layer exclusion or a conservative rule removes composition references and releases its lease while preserving a permitted base. Base/context exclusion cannot promote a resolved dependent layer into ordinary inventory. A layer shared by protected and permitted bases stays denied unless the exact named-rule layer exception leaves no other blocker. Unknown relation limitations and unrelated orphan inventory retain the accepted OCC/RULES semantics.

Replacement, reset, targeted withholding, real query/review changes, viewer close and source-scope exit abort the owned work, pause/detach native playback, release URLs and close bitmaps/canvases. Check authority after read, metadata/decode, poster creation, composition and before publication. A late completion cannot reattach a source or revive an old conversation. Cancellation does not dispose an otherwise current archive reader, and unrelated usable text/media remains available. Equivalent no-op query input preserves valid current work under FILTER-01.

## Verification, ownership and open gates

Media bytes must be legitimate small internal fixtures or reproducibly generated test-only outputs; relabelled text/static media does not establish codec or animation support. Browser checks exercise Library/Conversations/source/Back and cleaned bundle reopen using internal ZIPs, inspect actual native readiness/frames, record network/page errors and independently hash every saved original. Observe acquisition/decoder/lease peaks and cancellation, separating measured bounds from provisional admission limits. Preserve existing composition/export/thumbnail regressions. Run pnpm targeted checks, full units, build and affected actual-import browsers after implementation. No private archive, provider, paid call or external transfer is needed.

Manager assigns file ownership before implementation. Expected edits are a small media application module, a focused local-resource adapter, LocalAsset, thin Library/Conversations consumer changes and independent tests. Reuse imageComposition/localThumbnail/download helpers and the existing reader rather than duplicating them. Shared reader/normalizer/store ownership must transfer after OCC/FILTER work freezes; this proposal does not authorize concurrent mutation of QUERY/OCC code.
