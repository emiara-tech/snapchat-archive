# OBSERVATION-03: Explainable selected-history questions

Accepted bounded design against [Phase 7](../specs/phase-7.md), the masterplan, the existing observation calculation/job/view, and accepted QUERY/OCC/FILTER/COVERAGE/RULES/ORDERING/PERFORMANCE contracts. Workspace authored the design, root independently reviewed it, experience corrected OBS-D1, and root rechecked both comparison scope and selective authority. [The accepted design review](../reviews/observation-03-design.md) records the result. Original phase acceptance remains binding. Code, measurements and complete phase acceptance remain open.

## Owner outcome and remaining questions

The owner chooses a question, gets an understandable measured answer, and can open exactly the evidence that contributed. A surprising result is useful when its scope and limitations are clear. Counts cannot establish personality, emotional state, closeness, relationship quality or an official Snapchat streak.

Finish all six initial questions:

1. When does this selected history contain recorded activity?
2. Which proven direct exchanges have the most recorded events in a chosen period, and which counts belong to separate group or unknown-scope conversations?
3. How do the owner's observed words, phrases and emoji differ between two permitted years/periods or conversations?
4. What are the selected event kinds, declared media-appearance kinds and unique physical-original kinds?
5. Which time, source, authorship, membership and file limitations restrict those answers?
6. What does an explicitly opened curation comparison withhold, before versus after exclusion authority?

Each card includes a plain question/answer, exact semantic table, chosen scope, units, denominator, timeframe/zone, coverage explanation and evidence action. The reading and graphical modes consume the same packet. Rendering does not calculate facts. Keyboard evidence selection and return preserve shared query and current question/selection.

Optional tone interpretation remains separate and labelled with method/language/evidence limitations. This slice adds no sentiment score, personality inference, AI dependency or scripted response. No visual revamp or public synthetic mode is included.

## Current baseline and prerequisites

`computeObservations` currently accepts selected legacy events/assets but also receives aggregate participant/conversation labels. Its timeline combines events and standalone assets, Memories/map facts use accumulated asset time/location, language uses owner text without the complete flag/proof/period contract, and output lacks full query/review/denominator/coverage metadata. Its ID-only selection revision cannot establish equivalent timeframe or comparison authority. Existing indexed joins and corrected direct/group/unknown classification are useful foundations.

`observationJob` has one cancellable worker and a 5,000-record synchronous fallback, but copying/input/output bytes and completion are not bounded by those record counts. Existing tests protect basic joins, Unicode owner terms and calendar spacing; they do not establish all six questions or canonical occurrence parity.

Implementation prerequisites are complete byte-attested OCC evidence and exact authored-event/participation/flag facts, FILTER's committed canonical effective projection and field-level labels, COVERAGE's scoped packet/explicit comparison, RULES-derived authority where rules are enabled, shared exact calendar conversion, and the accepted canonical source-order amendment. Stage-one SHA alone is not complete capability. Bind final DTOs/interfaces to those accepted implementations before authoring this slice. Never approximate from `asset.timestamp`, accumulated location/title, observed participants or an old padded time key.

PERFORMANCE's concrete complete committed snapshot and bounded staging transport apply to any reused application worker. No observation worker may replace the committed collection with a page/cache or introduce another matcher. Independent query/order/evidence gates remain binding even if a small calculation passes.

## Small calculation/application boundary

Retain a small pure preparation and bounded read interface, with names frozen during preflight:

```ts
prepareObservations(input: ObservationInput, request: ObservationRequest)
  -> { ok: true, set: PreparedObservationSet }
   | { ok: false, errors: readonly SafeObservationError[] }

readObservationPage(set, { observationId, kind: 'values' | 'evidence', cursor })
  -> bounded stamped page | fixed typed failure
```

`ObservationRequest` has the fixed supported question IDs, owner/other/uncertain language scope, and an optional comparison of exactly two contained calendar windows or two permitted conversation IDs. It is not a filter DSL. The existing `observationJob` is the browser/worker adapter for these pure operations. Views request a question/comparison and render its packet; they do not assemble queries, count rows, expand recipients or recover missing data through raw lookups.

`ObservationInput` is the application's current permitted observation projection: exact FILTER stamp/canonical query, complete effective typed event/occurrence/media populations, chosen label/value proof, selected event authorship/known quote-copy facts, conversation scope/membership facts and the matching COVERAGE packet. Use explicit target namespaces. Join only exact selected targets at the same immutable evidence authority. Contradictory/dangling/foreign-revision facts reject before publication. A producer's explicit unknown classification stays unknown; a known owner ID cannot repair it.

The application adapter owns derived comparison-scope preparation through the existing FILTER/QUERY operation. A worker receives permitted records and approved sub-scope IDs once, not the complete unfiltered archive or independent caller-built matching stages. Both sub-scopes must be subsets of the primary effective population. Timed calendar-window sub-scopes explicitly use `unavailable: 'exclude'`, including when the primary query uses `include`; they retain every non-time facet, timezone and primary evidence/coverage authority. A primary `unavailable: 'only'` receives the fixed per-comparison refusal described below. No matcher callback, registry, second tokenizer, generic job framework, raw archive reread, Vue/Pinia, clock, storage, network or renderer belongs in the pure module. Typed exact calendar and shared language helpers may be reused/extracted only under explicit serial ownership and independent tests.

Explicit curation comparison is obtained from COVERAGE's all-review canonical comparison. Ordinary observation jobs receive its safe numeric packet, not excluded row text or import-wide labels. It has its own scope/query authority and cannot be supplied as an ordinary corpus.

## Packet, scope and evidence contract

Every observation carries stable question/metric ID, calculation/tokenization version, full session/fingerprint/normalization/occurrence/ordering/base-evidence and dataset/query/review/collection authority, canonical timezone/query, its own question parameters, authorship and source categories. Comparison-dependent packets additionally carry the exact comparison-request revision, derived queries and sub-scope IDs. Base activity, ranking, language and coverage packets do not inherit that revision. It names population, unit, numerator, denominator value/definition, optional normalized value/scale, explicit requested bounds and actual observed first/last instant, eligibility/omission counts, COVERAGE references, limitations and reproducible evidence handle.

Authority follows each metric's actual dependencies. A local comparison request or refusal leaves unchanged primary packets, their evidence handles, open pages and valid in-flight base work current. It cannot retag those packets, recompute them or invalidate them merely to advance comparison authority. Changing a base question's own parameters still invalidates its dependent packets and pages. The single immutable prepared set may retain those unchanged primary packets while replacing its comparison packets/state. This adds no second mutable store or generic dependency framework.

Raw counts are nonnegative safe integers. Ratios retain the exact numerator/denominator and scale; displayed rounding is identified and never replaces them. A zero/unknown denominator is unavailable, never NaN, infinity or a guessed base. An empty comparison population has raw zero and an unavailable rate. A zero category numerator with a nonzero evidenced population can be 0%. Zero retained data never means no activity/contact occurred.

Evidence pages identify exact contributing typed targets, per-target contribution count and scoped source IDs. A repeated word can contribute two tokens from one event; contributor-event cardinality is not the token numerator. Denominator evidence is a separate named population, not inferred from numerator targets. Word/phrase/emoji pages identify the matching normalized sequence and contribution count; original text remains unchanged. Highlighting, if implemented, must map normalized positions to supported original spans rather than pretend NFC/code-point positions are byte offsets.

Contributor ordering follows the amended canonical order. Ranking/value ordering is count descending with stable typed-ID or normalized literal code-unit ties; it does not change historical evidence order. Pages/cursors bind to the metric's complete primary scope, own question parameters and calculation authority. Only comparison-dependent pages/cursors also bind to the current comparison-request revision and derived sub-scopes. The application adapter checks those dependencies against the current prepared set before reading or publishing. A comparison revision change or refusal makes every previous comparison cursor stale; an unchanged primary word-page cursor remains valid. A stale/foreign/malformed cursor fails safely and cannot expand selection. Source opening checks current metric authority before and after exact local entry/ordinal/pointer read and uses the existing bounded source adapter. No first-path lookup or full raw history in packets.

Chosen titles/names require FILTER's exact permitted field proof. A selected occurrence may supply only its permitted parent-row context when its event fails a kind facet; it cannot make that unselected event part of activity or owner-language counts. Missing label proof yields `Conversation`/`Participant`, never a private ID, filename or retained aggregate label. Owned diagnostic evidence is scoped; unowned diagnostics remain deliberate review inventory. Denied candidate, layer, event, occurrence and source canaries must be absent from every ordinary result, explanation, evidence page and scene input.

That denominator requires explicit finite complete calendar bounds in the selected zone. The chosen duration is a user-defined comparison window, not verified export coverage.

## Writing comparisons and shared language policy

For two-period comparisons, accept half-open local calendar-day windows with valid finite bounds. Each whole window must fit within the primary query's current time/year constraints. Reject windows spanning an unselected year hole or extending outside an active range; offer an explicit normal shared-filter action rather than silently broadening/intersecting the request. Preserve every non-time facet, authority and exact timezone. Use the existing canonical operation to prepare each approved sub-scope with its requested calendar bounds and explicit `unavailable: 'exclude'`. Do not inherit `include`, `auto` or `only` into a timed cohort. Each returned event/occurrence population must be contained in the primary effective population under that same immutable base-evidence and primary query/review/coverage authority; bind the derived canonical query and IDs to the separate comparison-request authority.

Date-only, absent, invalid and un-zoned evidence remains in the primary population/coverage according to the unchanged primary query. It contributes to neither timed window and acquires no midnight, timezone or period from a recorded date, event kind or another occurrence. Primary `unavailable: 'only'` refuses the timed request with fixed typed state/code `timed_comparison_unavailable_scope` before preparing calendar sub-scopes. It cannot broaden the primary query, return fabricated zero-period measurements or replace already usable primary cards. The refusal is local to the comparison request under the current primary stamp; existing counts, language and coverage cards retain their current valid packets. An explicit shared-filter change remains an owner action.

Conversation comparison similarly narrows to two exact permitted conversation IDs under the primary query's existing unavailable policy; the timed-window override does not silently turn that comparison into a time filter. Comparison controls and refusals change only comparison-request authority and dependent packets/jobs/pages, not shared filters, decisions, coverage scope, collection authority or base question parameters. Advance comparison authority when the request changes, including a refused request. Previous comparison values/pages/jobs then lose current authority and cannot appear as fallback for the new request. Primary pages, evidence handles and work with unchanged dependencies remain valid. QUERY temporal semantics remain unchanged and no second comparison matcher is introduced.

Show each period's raw event, eligible-message/token/phrase-window/emoji counts, active-day count and full selected-calendar duration. Compare matching rates with their own explicit denominators: equal word/token rates, emoji/message rates, and retained events per selected calendar day. Calendar duration counts dates, not hours; DST does not divide a day into fractions. If a base is unavailable or a population is empty, that metric is unavailable independently of other valid metrics. Sparse n=1 comparisons may show exact descriptive rates with sample size and a limitation, never significance, personality or a reliable style/persona claim.

Freeze one shared calculation/tokenization policy for observations and year profiles during serial preflight. Proposed new policy uses NFC then locale-independent lowercase for word matching, preserves letters/marks/numbers with supported internal apostrophes, omits HTTP(S) URL spans, and applies no stop words, stemming, transliteration or language detection. Complete emoji grapheme clusters are recognized before word tokenization and omitted from the word stream, so a keycap is not both a digit word and an emoji. Word-adjacent 2/3-token phrases stay within one message; punctuation does not create another message and no phrase crosses message boundaries. Counts/rates are over tokens, not a claim of linguistic word segmentation for every language; contiguous unspaced text has a disclosed limitation.

Whole grapheme clusters preserve joined families, modifiers, regional flags, variation selectors and keycaps. A missing/unsupported segmenter makes emoji and any language metric depending on its unvalidated emoji mask unavailable; activity/ranking/proportion cards remain usable. No split-code-point fallback claims complete emoji or silently counts a keycap as a word. NFC does not rewrite original text or copy identity. Repeated identical text is not inferred copied content. Known flags require supported source proof; absence of a flag is not proof of original authorship. Freeze regex/Unicode/grapheme method and supported runtime versions with independently worked fixtures before compatibility claims. Any policy change increments calculation/tokenizer authority and invalidates profile/observation caches; the current helper's unnormalized token behavior cannot silently share the new version label.

## Job, cache and resource preflight

Freeze implementation policy before code, then measure it. Proposed admission is one active observation worker/job, one replaceable pending latest request, one completed current set and one staging set. Equivalent canonical query and metric parameters preserve the valid packets. A comparison-only request change invalidates comparison-dependent packets, jobs and pages, while unchanged base packets/pages/work retain their existing authority. Publication validates each packet against its actual current dependencies; an obsolete comparison revision cannot reject or retag an otherwise valid base completion. A single immutable current set may carry retained base packets and new comparison packets or refusal state. It does not introduce another mutable store, extra active worker or unbounded completed sets. Real committed query/review/rule/association/session/zone/version changes invalidate every old dependent value/example/page/scene before it is presented under new authority. A pending FILTER transaction retains C1's coherent scope until actual commit; after C2 commit, C1 is not current fallback. No cached excluded canary is available to another consumer.

Use the accepted bounded worker transport policy: at most 1 MiB fixed-field whole-record batches, one outstanding plus one pre-encoded batch per direction, 2 MiB queued bytes per direction, 120-second total preparation/transfer and ten-second ACK guard. Observation input, including all approved comparison metadata, has a proposed 256 MiB admitted total. Shared permitted text/facts are transmitted once with sub-scope target IDs, not duplicated for two windows. Full calculation/output/evidence index admission is proposed 64 MiB; one incomplete staging assembly only. Oversize complete records, input or result reject honestly without truncating counts/corpus into a claimed success. Exact byte limits are admission choices, not browser heap or hardware guarantees.

Bound reading/value/evidence pages to 50 rows, 256 KiB encoded page, 128 KiB displayed text, 4096 displayed code points per contribution, 256 per label and 16 references per contribution reference page. Keep at most two current pages, 512 KiB encoded/256 KiB displayed text total. Full contributors and exact token/denominator counts stay in the admitted prepared set; page preview truncation is explicit and cannot affect calculations. Long-row placeholders retain the permitted exact target and source action. Reuse SOURCE/COVERAGE limits and MEDIA lease/decode ownership for actual inspection; this task does not acquire textures or keep original byte buffers. No raw source document is copied into a chart packet.

Worker absence/failure is a typed capability state. Do not silently run a large synchronous fallback. Cheap already-committed collection counts may remain available, but costly cards require the worker until a separately measured and reviewed finite fallback is accepted. A per-card unsupported language method, empty base or ordinary calculation failure leaves other current cards usable, with its own retry/state. Foreign primary revision/proof input invalidates the whole proposed set. Cancellation follows the owned work's dependency scope. A comparison-only cancellation/change/refusal cannot clear primary pages or invalidate a base job whose dependencies remain current. Canceling a job terminates its actual owned work and drops its staging/messages/listeners; reset or primary replacement rejects every obsolete dependent output and clears its authority. No automatic reissue of stale state.

Each metric cache key includes its exact canonical primary query/timezone, complete FILTER stamp, own question parameters and the scoped authorship/eligibility/calculation/tokenizer versions it uses.
