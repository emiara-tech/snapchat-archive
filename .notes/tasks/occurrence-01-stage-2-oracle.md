# OCCURRENCE-01 stage-2 literal oracle

These independently authored counts were accepted in the [general preflight](../reviews/occurrence-01-stage-2-design.md). The [exact binding](occurrence-01-stage-2.md) and its [review](../reviews/occurrence-01-stage-2-binding.md) add field-domain, admission and retained-ID cases. Original phase gates remain binding. These are test expectations, not implemented outcomes.


Each example uses internally authored actual ZIP entries plus independently computed document SHA and expected exact physical ordinals. Labels below are handwritten logical oracle labels, not claimed production ID formats. Freeze literal retained legacy IDs separately before any changed partition. Parent/row/slot identity and set cardinality must be checked independently of the new producer.

| Case | Handwritten expected facts |
| --- | --- |
| C1. Repeat slots | One chat event E at `/fixture-person/0` has Media IDs `["A","A","B"]`. Occurrences O0/O1/O2 have reference ordinals 0/1/2, all own E, and distinct occurrence/reference IDs. A and B are two exact originals; historical count is 3, physical original count is 2 and all three references are confirmed. Old A's conflated reference/link ID belongs to neither split slot; the unique B reference may retain its valid ID. |
| C2. Malformed gap | E has `["A",null,"A"]`. Under root's B1 resolution there are exactly two supported occurrences, at ordinals 0 and 2, plus one malformed-slot diagnostic at ordinal 1 and an unknown-reference remainder. There is one physical original and no request or guessed attachment for null. Neither known supported count 2 nor the diagnostic establishes that the uninterpreted slot is a known historical appearance. |
| C3. Explicit-list variants | Authored supported string-encoded array `["A","A"]` and delimited field `A; A` each retain two slots under their distinct declared parser rule. A wholly unsupported object field produces only its diagnostic, with no invented attachment total. A remote URL token is never fetched or matched by substring. |
| C4. Genuine repeated Memories saves | Saved Media document has two byte-identical recognized rows at `/Saved Media/0` and `/Saved Media/1`, both referencing A. There are two save occurrences, repeat ranks 0/1 and one physical original. A copied exact document adds two row-copy provenances and no saves. An overlapping different-byte single-row document adds a third save. |
| C5. Conflicting metadata and proof | Two Saved Media rows use Date `2020-01-01 01:00:00 UTC` and `2020-01-01 02:00:00 UTC`, Media Type Image, and supported Download Link mid A. Both target the current exact main path `memories/2020-01-01_A-main.jpg`; different calendar dates would target different files under B4. Their literal locations are `LOCATION-ONE` and `DENIED-LOCATION-CANARY`. Both captions remain null. Their own time/location/proof facts survive independently and sources open their exact rows. A later pure query excluding the second row cannot expose its location/time/source through the first or a minimal resource. The original bytes remain locally inspectable. Stage 2 preserves facts; later canonical publication verifies this projection. |
| C6. Mixed uses of one original | Combine C1's three slots with C4's two saves, where B remains a separate original. Total supported historical occurrences are 5, event count is 1 and physical originals are 2. A's four supported uses do not create four files. Copy either proven document without changing logical counts. |
| C7. Ambiguous and missing | One supported slot token D has available distinct originals D0/D1, another token MISSING has no file, and a third references A. There are 3 historical references, one candidate reference with two candidate files, one established missing record, and only A is confirmed inline. Candidate proof for D0 contains its own physical source plus permitted reference proof, never D1's exclusive canary. Missing has entry null and no physical bytes/hash. |
| C8. Layer-only reference | A supported token exactly names available layer L. Its slot remains explicitly unresolved/unlinked with a diagnostic, with no original candidate or confirmed attachment. L remains its independently classified physical layer. It gains no historical date or recipient. |
| C9. Copies and duplicate names | Exact chat and Memories document copies at different source/entry ordinals preserve source membership and slot/row identities. Two same-path physical originals in one ZIP at authored ordinals 2 and 10 stay separately addressable and ambiguous; numeric row/reference order cannot choose a physical winner. |
| C10. Containers and identity | Thread `fixture/a~b` has row 2 and row 10 and exact escaped container `/fixture~1a~0b`; another container has a numeric-looking key. Store the actual array indices and pointers before skipping an invalid row. Do not claim that numeric-looking object-key enumeration establishes textual byte order. Input/part reversal preserves valid IDs and proof memberships. |
| C11. Empty/unreadable/missing | A recognized empty Saved Media array has zero known saves. An empty/unknown-only object is diagnostic and contributes no recognized save. A Location-only row contributes one known save with unavailable time/kind/reference facts. A recognized row with invalid Date or unknown Media Type still contributes one known save plus uncertainty. Missing section, unreadable document and these row states remain distinct. A supported row with missing bytes still retains one save; an unreadable document's historical remainder is unknown. Full query capability remains null in every stage-2 fixture. |
| C12. No invented owner authority | Current legacy AssociationDecision records with only linkId/action/timestamp cannot produce owner-confirmed proof. No English basis string or partial constructor gets a fabricated decisionId/occurrence target. Baseline exported facts and source bytes remain unchanged. |
| C13. Declared media without reference | A supported IMAGE event with an absent Media IDs field retains one event, zero attested supported reference occurrences and an explicit unknown-reference limitation; it does not claim zero historical appearances. A wholly unsupported object field has its exact diagnostic and the same no-invented-slot policy. A separate explicit safe MISSING token establishes one known unlinked occurrence with no bytes. An explicitly supported empty reference array has a known zero slot total, distinct from absent/uninterpretable fields. |
