# PERFORMANCE-01

Accepted bounded design from [Phase 2](../specs/phase-2.md), [Phase 4](../specs/phase-4.md), [Phase 5](../specs/phase-5.md), [QUERY-01](query-01.md) and the [OCCURRENCE](occurrence-01.md)/[FILTER](filter-01.md) contracts. [Design acceptance](../reviews/performance-01-design.md) records independent review, distinct correction and recheck. Admission budgets below are policy pending measurement, not measured guarantees. This contract accepts no code, benchmark, browser performance or full phase.

## Owner outcome

The owner can move through a long recorded exchange, jump to a memory and change filters while the app remains usable. A bounded thread still shows the correct neighboring evidence. Background work cannot revive excluded context or replace a newly imported archive. The owner sees real progress, can cancel and keeps usable text when a media preview fails.

Original Phase 4 criterion 7 is binding: a generated 100,000-event conversation renders a bounded window, answers a jump without rendering the entire thread and keeps direct controls responsive within 100 milliseconds on a recorded desktop benchmark. Phase 2 requires local worker indexing/querying and stale-response rejection. Phase 5 requires one canonical collection across consumers. Moving work to a worker or limiting DOM nodes alone proves none of those gates.

## Current source baseline

- `src/views/ConversationsView.vue:19–32` caps rendered thread events at 60 but derives conversations and full thread arrays from reactive selection scans.
- `ConversationsView.vue:40–51` scans all links for each event's candidates, scans all matching events for each summary/date and uses linear event/date jumps. Its template line 75 scans selected events again for every conversation. Window size does not bound that work.
- `src/stores/workspace.ts` computes legacy filtering on the main thread, rebuilds joins on review changes and supplies full event/asset arrays to pages. FILTER-01 replaces that policy before this task can optimize its application adapter.
- `src/lib/dataset.ts:57–81` reads/decodes documents before a one-shot normalization worker. `dataset.worker.ts` returns the whole normalized dataset and is terminated. OCCURRENCE-01 owns byte attestation, corrected identity/time facts and operation cancellation; this task cannot substitute a new parser.
- `src/lib/observationJob.ts` has an abortable one-shot worker and a bounded no-worker fallback. `observations.worker.ts` illustrates local calculation I/O, not a canonical query worker. The current job's copying/transfer costs are unmeasured for this gate.
- `src/lib/archiveQuery.ts` is the sole accepted matching/effective-exclusion operation. Its Q-S1–Q-S5 correction loop was accepted in `7499ad46`; the source-order amendment remains separate. Its complete result is useful for deterministic pure tests, but copying every record for every page is not a required rendering strategy.
- `src/lib/snapArchive.ts` owns exact-entry reads and media URLs. `localThumbnail.ts` already limits thumbnail decoding to three tasks. Preserve those ownership contracts and the accepted MEDIA composition/decode limits; do not add a second reader or global media cache.

## Prerequisites and ordering correction

QUERY code findings Q-S1–Q-S5 are fixed and independently rechecked. OCC must supply complete byte-attested runtime evidence, numeric row/reference ordinals, stable physical/source identities and normalization compatibility. FILTER must supply atomic canonical state, permitted labels, current session/evidence/query/review authority and scoped consumer interfaces. No incomplete legacy dataset may be cast into a worker capability.

There is a separate ordering-contract prerequisite. Original Phase 4 requires source-order ties and undated source order. Accepted QUERY-01 currently ties by stable ID; current hashed event IDs do not establish recorded source order. Root has explicitly retained the original requirement. After producer identity/order facts freeze, bind and implement [the reviewed canonical ordering amendment](ordering-01.md) before thread acceptance. The amendment must compare numeric row/reference ordinals within documents, retain byte-copy provenance, document stable cross-document ordering without claiming chronology between unrelated undated documents and preserve query/calculation/portable-state version authority. Do not resolve this by a page-specific or worker-specific sorter. PERFORMANCE-01 consumes the amended canonical order unchanged. This draft introduces no new ordering code or types.

## Bounded application and worker behavior

Keep one canonical matcher. The worker invokes the accepted `selectArchiveCollection` over immutable prepared evidence and validated query/review/deny snapshots. Indexes may organize that result; they do not reinterpret time, literal text, membership, review inheritance, candidate proof or exclusion. Ordinary indexing uses effective records. Deliberate review indexing has an explicitly different scope/stamp and never supplies ordinary job/export input.

A small pure conversation module prepares summaries and ordered per-conversation positions from the canonical result and permitted label/authorship/coverage facts. It serves bounded summary/thread pages and focus/date/first/last requests from those positions. Agree the minimal prepare/read interface during preflight. There is no filter callback, generic search language, command bus, plug-in index registry or independent matching calculator.

Preparation creates an event-ID position index and per-conversation ordered positions in one pass over the selected result. Summary count, permitted preview and recorded range come from that population, with direct/group/unknown scope and membership limitations supplied by exact evidence facts. A preview cannot read an aggregate title/name or unselected first event. Counts distinguish events from appearances/files. A missing text/media record remains a record, not another search hit or a fabricated empty exchange.

An event jump resolves its exact ID through the prepared index. A date jump uses the canonical zone/exact instants and prepared calendar positions; it never slices a UTC legacy timestamp or scans every event in a view. Unavailable/date-only evidence remains labelled and follows the amended order. A target outside the permitted thread returns a typed outside-scope result with explicit constraint/review actions. It never broadens filters or revives a denied parent. A selected appearance whose event fails an event-specific facet may open its permitted occurrence evidence through FILTER's existing context contract; it does not force that event into canonical thread IDs.

Pages contain the current scope/stamp, exact ordered target IDs, permitted row/attachment/proof fields, total population units and a bounded cursor/window. Cursors bind to import session, immutable evidence, canonical query/review/collection revision, conversation and review mode. Reject malformed/out-of-range/mismatched cursors. First/last/date/event jumps place the requested eligible target and neighbors in a bounded window. Source navigation, viewer close and Back restore the corresponding window/focus only if its authority is still current.

The browser adapter owns worker lifetime, scheduling and transport. Keep at most one active query/index computation and one replaceable pending latest request. Each completion carries exact requested authority and a monotonically scoped request ID. Check authority before work/read and before publication. Superseding, canceling, resetting, replacing or disposing stops actual owned work, not merely its result display. If synchronous canonical evaluation cannot observe a cancel message, terminate that owned worker before starting its successor. Reinstallation/recovery uses current immutable evidence and must be included in responsiveness/resource measurements. Never automatically replay an application decision or stale prepared proposal after worker recovery.

Worker installation should retain immutable prepared evidence once per active authority, rather than posting all rows for every filter, conversation or page request. Keep full matching/index calculations off the main thread. Transport bounded pages/metadata instead of eagerly copying every nested event/source/raw object into every view. P-D1 fixes complete committed collection/index ownership in the main-thread application snapshot and uses an independently owned staging worker. Worker-owned committed collection handles are outside this slice. Complete canonical results travel through P-D2's bounded fixed-field batches; only display pages reach views. FILTER retains one authoritative complete collection, exact counts and frozen targets.

Measure validation, structured cloning/installation, output transport, Vue publication and window rendering as well as worker CPU. A worker that blocks the main thread while serializing/deserializing a full history still fails the direct-control gate. No new query, choices, summary and rows may be exposed as a mixed old/new authority. During asynchronous preparation, show explicit pending work and preserve the last coherent committed snapshot or a truthful pending state; accepted FILTER owns the final atomic transaction and invalidation rules.

## P-D1: Committed snapshot and staging ownership

This slice keeps FILTER's complete immutable committed collection and its prepared conversation indexes in the main-thread application snapshot. Only bounded display pages reach views. A worker-owned committed collection handle is outside this slice; it requires a separately reviewed FILTER contract before implementation. Complete scope/target enumeration for bulk, rules, coverage, profiles and export always reads the same committed canonical collection, never the visible page or a worker cache. Display truncation cannot alter matching, counts, full text, authority or frozen targets.

The browser adapter owns at most one live staging/installed worker, one active preparation and one replaceable pending full-query replacement intent. The complete committed C1 snapshot/index survives staging termination. Installed immutable baseline evidence belongs to the import session and base-evidence authority, independent of query/review revisions. Reuse it across ordinary query operations in that worker; after actual termination/failure, a successor reinstalls only the current baseline through bounded transport. Conversation/page reads use the committed prepared indexes and do not post the whole baseline or rerun matching. At most two collection generations exist: one committed and one staged. Temporary transfer copies of the staged generation are separately subject to P-D2's encoded/assembly limits; this does not claim two physical memory copies or a total heap bound.

Preparation starts from the exact committed FILTER aggregate and expected session/evidence/query/review/collection stamp. It validates the requested query/choices/rules and invokes the canonical selector and pure conversation index preparation in staging. New query, counts and rows stay uncommitted. A ready candidate means the whole canonical collection, complete prepared index and bounded required metadata have been assembled and validated, with a complete transport footer and exact authority. The store then performs FILTER's final expected-stamp check and one aggregate commit. Only after that commit are obsolete proposals/jobs/leases invalidated and old committed references released. Partial/stale/failed transport never becomes a ready candidate.

Cancel, supersession, worker loss before ready or invalid restore discards staging and preserves C1, its complete indexes, history, proposals and useful leases. A worker lost after a fully ready candidate cannot erase data already owned by the application. The candidate may commit only if its original expected stamp still matches; otherwise it discards. Loss after the one commit cannot roll back or invalidate that complete new snapshot. A later operation can reinstall current baseline while existing pages/target enumeration remain usable. Import replacement invalidates both authorities and disposes owned staging, committed indexes, queued intent and resources under the existing lifecycle.

Mutation requests are explicit. While one effect/restore/review transaction is pending, another such mutation returns a typed busy result without consuming proposals, changing history or automatically retrying it. Patch commands also return busy while a real mutation is pending; they are not silently merged from stale committed state. A fully validated, query-only full replacement with the same unchanged base/current authority may explicitly supersede a pending query-only operation. It replaces the one pending full intent and reports the superseded result; it never overwrites a rule/review/restore transaction. Equivalent no-op or invalid input does not replace valid pending work. Once staging actually stops and its owner is released, only the latest still-current complete intent starts. This serializes accepted state changes and leaves cancellation available; it introduces no command bus or hidden action replay.

The final FILTER adapter interface must retain complete main-thread snapshots and this prepare/ready/commit/discard lifetime. No alternate worker-handle representation is considered an accepted equivalent. Index transport is a derived exact sidecar prepared with the same authority, then installed with the collection, not a second mutable store or a separately committed generation.

Literal lifecycle cases start from C1 with known IDs outside both cached windows and a known complete bulk target list. Canceled/superseded C2, invalid restore and worker loss before ready preserve that full list and permit a fresh C1 page outside the cache. Ready-candidate loss may publish only the complete current C2 after the final stamp check; loss after commit preserves C2. Replacement during transfer prevents any old C1/C2 publication. Pending mutation busy results preserve history/proposal consumption; explicit latest full-query supersession produces only its known canonical targets. Observe the one-worker/two-generation/one-pending ceilings and absence of excluded canaries.

## Resource and failure contract

P-D2 freezes finite window, whole-page/text/cache, full-generation, flow-control and assembly limits. They require independent verification/measurement before code acceptance. Bounded display is explicit and cannot alter complete matching, source evidence or population. More attachments in one event still use accepted MEDIA on-demand ownership rather than unbounded DOM/native acquisition.

Keep one current baseline and one in-flight prepared calculation, with bounded page cache rather than an unbounded cache for every query/room. Cache keys include full authority, canonical values and explicit review scope; equal count/fingerprint alone is insufficient. Apply/no-op/failure behavior follows FILTER: equivalent input and failed restore leave useful work intact; a real authority change invalidates relevant pages/jobs/proposals and leases. Cached matched/excluded packets never become ordinary fallback data. Review history must not retain full raw dataset/query-result copies for every transaction.

Closing a viewer/page or withholding/replacing its resource releases through the originating reader, aborts pending decode/composition and rejects late attachment. Reset/replacement/disposal terminates owned workers, removes listeners, drops indexes/page caches and releases URLs/bitmaps/buffers once. Original File/ZIP/media bytes remain unchanged. Native garbage collection timing is not a deterministic zero-memory guarantee; verify owned references/resources and report available process/heap measurements honestly.

Worker absence/failure, invalid capability, resource ceiling, missing pointer, unsupported codec and cancellation are distinct typed states with safe errors. A 100,000-event request cannot silently run the same blocking calculation synchronously after worker failure. Any small-input fallback has a separately reviewed finite ceiling and uses the same pure modules; the large gate remains unavailable in that capability state. Retry retains valid local selection and starts only current authorized work. Failed media decoding preserves thread text and navigation. No archive evidence, query, IDs, filenames, fingerprints or diagnostic source values leave the device or enter analytics.

## P-D2: Total display, cache and transport admission

The finite limits below are admission policy pending independent actual-import measurement. They preserve the selected population; they do not prove native heap bounds or the original 100 ms gate.

| Data/owner | Finite initial limit |
| --- | --- |
| Thread window / summary page | 60 events / 50 conversation summaries |
| Display page | 2 MiB UTF-8 encoded complete page; at most 1 MiB encoded displayed text in that page |
| One displayed event | At most 4096 Unicode code points of text; each title/name/caption/location/filename display at most 256 code points; at most 16 source/candidate reference IDs per bounded row reference page |
| Completed display cache | Two thread windows including the active window, plus one active summary page; at most three pages / 6 MiB encoded page data / 3 MiB displayed text in aggregate |
| One installed baseline or complete prepared generation | At most 256 MiB encoded admitted transport data, including all fixed result/index/metadata fields |
| One transport batch / exchange window | At most 1 MiB per batch; one unacknowledged batch per direction and one already encoded next batch, at most two pending messages / 2 MiB per direction |
| Incomplete assembly | At most one staging generation / 256 MiB accumulated encoded data; no unbounded response list or second partial assembly |
| Transfer/preparation timeout | 120 seconds overall per install/preparation/transfer; at most ten seconds without acknowledgement for one outstanding batch |

A displayed row uses an explicitly labelled preview/truncation result while preserving its exact target, canonical order and complete population count. Overflow never silently removes the event or truncates canonical matching text, quotes, export/profile data or frozen target lists. Additional permitted source/candidate references page through the existing typed evidence/navigation adapter. Source inspection retains its separate accepted bounded capability. If even the bounded target/placeholder cannot fit a page, return a fixed row-too-large capability placeholder with its exact permitted target and source action, rather than substitute another event. Page packing preserves stable target order and reports exact next cursor; it may return fewer than 60 events under the byte cap but cannot omit or repeat a target across pages. MEDIA's global 24 card/pipeline/foreground acquisition limits still apply independently.

Transport uses a fixed versioned collection/index protocol, not one giant serialized JSON value split into arbitrary strings. Whole canonical records and exact prepared index arrays are batched within their known result fields; a batch is decoded/validated independently and appended only to its fixed staging field. A canonical record exceeding a single-batch ceiling fails this operation honestly and preserves C1; it is not truncated into a claimed complete collection. Final fields retain every selected record and target. Yield main-thread processing between bounded batches; do not perform one final 256 MiB parse, clone or index reconstruction on publication. Preparation already supplies the complete derived index. Its bounded batch installation and final atomic reference commit must be included in the actual latency measurement.

Every batch identifies protocol/version, direction, operation/request ID, exact authority, fixed field, sequence and admitted encoded size. Reject unknown fields, duplicate/out-of-order batches, wrong counts, malformed/stale authority and incomplete footer. Expected full field totals/counts and cumulative actual encoded bytes must agree before ready. Unknown or inconsistent data never publishes partial counts. The sender waits for the matching acknowledgement before another post; at most one pre-encoded next batch may coexist. A missing acknowledgement, total timeout, oversize response or authority change aborts the owned operation, clears queued batches/assembly and preserves committed state. Original baseline installation and outgoing query/review snapshots obey the same flow-control and total-size policy. No unbounded postMessage backlog or display cache is permitted.

Complete source data, matching and bulk/profile/export target enumeration use the complete committed collection/index. Page records are a distinct bounded display type with explicit truncation flags; a page cannot be passed as a complete QUERY result or AI/export corpus. The committed/staging generation limits account for two admitted generations, with one stage assembly and bounded in-flight batches; available runtime/process measurements must disclose additional object/string/native copies rather than report encoded bytes as heap consumption. Capacities above policy produce an honest resource-limit result without changing current authority.

Literal public tests include a single long permitted text row with known truncation marker/target, adjacent events across byte-boundary pages, a requested page whose small metadata-only placeholder is too large under a test override, canonical target enumeration beyond all cached windows, enough individually legal batches to exceed total generation allowance, duplicate/partial/stale packets and a receiver that acknowledges slowly during rapid supersession. Observe complete cache/assembly/pending-byte/worker counts, once-only cleanup and unchanged C1 on rejection. Genuine supported raw 100,000-event ZIPs still contain and select all 100,000 records; bounded presentation cannot replace that fixture with a smaller history. Completion-time goals remain separately measured; a finite 120-second failure deadline is not a promised satisfactory query duration.

## Recorded desktop measurement

Freeze the measurement procedure before optimization. Use a production build and the actual 100,000-event ZIP. Record exact revision, fixture digest/size, physical desktop CPU/RAM/OS/browser/version, actual headed/visible display setup, viewport/refresh conditions and competing load. Do not infer hardware from a container's reported vCPU/model or present headless/software measurements as a verified representative desktop run. Headless browser checks remain useful functional regressions with their environment labelled. Missing access to the designated desktop keeps this measured gate open; it does not block local deterministic correctness work or require a paid service.

Measure at least ten repetitions of each frozen direct-control action after initial import, and separately disclose cold startup/index installation and any warmup. The actions include conversation selection, first/last/event/date jump, typed filter change/reset, pending-work cancel, exclusion/undo and source/viewer close. Record input dispatch, processing start/end and first painted meaningful feedback through browser Event Timing/performance marks plus observable DOM state. A button press acknowledged by a spinner is pending work, not completed selection/navigation. Do not substitute automation command round-trip time for measured browser interaction delay.

The original direct-control threshold is at most 100 ms for every observed action in the declared scenario; a percentile alone cannot hide an over-budget action. Report sample count, maximum and distribution, failures and dropped/superseded work. Repeat while a large canonical query is active and during worker cancellation/reinstallation. If measurement resolution does not establish the threshold, report inconclusive rather than pass.

Report completed worker-query time, index preparation time, returned-window/navigation time and source/media readiness separately from main-thread feedback. They have no invented 100 ms completion promise. Agree practical completion budgets during preflight from measured baseline/user impact; proposed budgets remain proposals until accepted. A responsive pending control cannot be reported as an already answered jump. Include main-thread long tasks, rendered row/node count, active/retained worker/page/resource counts, transport byte peaks and available process/heap observations with their measurement limitations. Preserve synthetic results only; collect no private archive benchmark payload.

## Acceptance and delivery order

1. Accept the producer ordering facts and separately reviewed canonical ordering amendment, QUERY corrections and FILTER runtime projection/authority interface before implementation.
2. Author the small pure conversation index/page behavior test-first with independent parity and numeric tie/undated fixtures. Its inputs are canonical records, not raw export parsing or a new matcher.
3. Integrate the bounded worker/browser adapter and existing conversation controls. Keep domain preparation outside the view, while scrolling, focus and rendering remain in the view. Verify actual stop/stale rejection and cache/resource ceilings.
4. Import the real synthetic 100,000-event ZIP, measure the frozen production desktop procedure and fix any observed budget failure. Passing a smaller fixture, injecting a prepared DTO, counting 60 nodes or running only headless workers cannot close the gate.
5. Run pnpm targeted public tests, build, full units and affected actual-import browsers. Freeze source ownership and evidence for independent original-spec/standards review, a distinct fixer and reviewer recheck. Root records measured outcomes and remaining gates.

This slice leaves full scene/GPU performance, complete supported-media journeys, profile/observation algorithms, external transfers, funded AI and deployment acceptance separate. It contains no public demo, fabricated user history or future visual revamp. No entire original phase is complete merely because the index/page tests or worker adapter passes.
