# Privacy audit — 2026-09-05

**Valuation: COMPROMISED**
Commit: `7c9e638` on `dev`
Baseline run — first audit, no prior report to compare against.

The archive handling is genuinely clean: no network calls, no storage APIs, no
analytics, no service worker, and reverse geocoding runs against a bundled city
table instead of a geocoding API. That is the good version of this app, and most
of the charter holds.

The valuation is COMPROMISED on one line of CSS. `src/style.css:1` pulls fonts
from `fonts.googleapis.com` on every page load, which contacts Google — with the
visitor's IP, User-Agent, and referring page — before they have done anything.
The privacy page tells them no third party is involved. For an app whose entire
argument is "the company holding your memories is not on your side", shipping a
silent request to Google on the privacy page itself is the most expensive kind
of small bug. It is also a one-line fix.

Second, the privacy page describes an export feature that does not exist yet.

## Findings

### F1. Google Fonts is contacted on every page load — C4

**What:** A remote CSS `@import` to `fonts.googleapis.com`, which in turn pulls
font files from `fonts.gstatic.com`. Both requests carry the visitor's IP
address, User-Agent, and `Referer`. No archive content is exposed — this is
metadata egress, not data egress — but it is a third-party request the user was
told does not happen.

**Where:** `src/style.css:1`

**Why it matters:** Three compounding reasons. The privacy page states "No
third-party analytics SDKs, tracking pixels, or advertising scripts are loaded
by this app" (`PrivacyView.vue:50-53`) — narrowly true, since a font is none of
those three, which is exactly what makes the sentence misleading rather than
false. The request fires *on the privacy page itself*. And German courts have
already ruled that embedding Google Fonts without consent violates GDPR by
transmitting IP addresses — for an app whose origin story is a GDPR request,
that is a pointed irony.

**Options:** self-host the two families and drop the import; use a system font
stack; keep it and rewrite C4 to "the app makes no network requests except
loading fonts from Google." The first preserves the promise; the last preserves
the fonts.

### F2. The privacy page describes an export feature that does not exist — C5

**What:** `PrivacyView.vue:60-67` states, in the present tense, that exports save
directly to your machine and that Goodbye Chat does not receive a copy. There is
no export implementation in `src/`.

**Where:** `PrivacyView.vue:60-67`; absence across `src/`

**Why it matters:** The statement is currently harmless — you cannot leak
through a feature that does not exist. The risk is ordering: the promise is
already published, so whoever builds the export later inherits a constraint they
may not know they are bound by. FLOW step 8 specifies a downloadable zip with a
bundled `index.html`, which is compatible with the promise — but only if it is
built that way deliberately.

**Options:** move the section to future tense or remove it until the feature
lands; or treat it as a spec and link it from the export task in `TODO.md`.

### F3. Memory download links point at Snap's CDN — C1, forward-looking

**What:** `src/lib/snapchatParsers.ts:111-141` parses a `Download Link` field
out of `memories_history.json`. Nothing fetches these today. But the natural
next feature — actually retrieving full-resolution memories — means requesting
them from Snap's servers, one request per memory, tied to the user's own memory
IDs.

**Where:** `src/lib/snapchatParsers.ts:111-141`

**Why it matters:** It would tell Snap, in real time, exactly which memories a
departing user is pulling and when. The app would be reporting the goodbye to
the company being left. This does not break C1 today — the parser only reads a
string — but it is the single most likely way C1 breaks in future, and it will
feel like an implementation detail when it happens.

**Options:** none needed now. Flag it in the export task so the decision is made
with eyes open, and disclose it plainly if built.

### F4. `.notes/` is tracked and accumulating media — C8

**What:** `.notes/` is committed and holds working documents. This session added
`talking-head-plan.m4a` (5.3 MB), `talking-head-plan-xai.mp3` (7.5 MB), and a
narration transcript. `.gitignore` has no rule for audio or for `.notes/` media.

**Where:** `.gitignore`; `.notes/`

**Why it matters:** Currently clean — nothing personal is in there. But this is
the drift path: `.notes/` is where drafts, references, and reference *photos*
naturally land, and the talking-head plan explicitly calls for personal
reference images. A `git add -A` puts whatever is sitting there into public
history permanently.

**Options:** ignore audio and image types under `.notes/`; or keep personal
material in the `talking-human/` folder the plan already specifies outside the
repo.

## Stated position on remote services (C6)

Recorded so future drift is visible. As of 2026-09-05 the author has decided that
LLM and text-to-speech **may** use remote providers with user-supplied API keys,
described as provisional ("for now"). No such provider is wired in yet, so C6 is
N/A rather than at risk.

`.notes/browser-talking-human-deliverables.md` still specifies local-only speech
in five places (lines 40, 109, 110, 125, 153), including offline verification
steps and "do not enable cloud TTS". That document and the current decision
disagree; whichever is stale should be updated before implementation starts.

The working position from the last review: remote speech is low-risk, since it
only ever sees a line of already-generated dialogue. A remote LLM is the
sensitive one, because its prompt would be archive content — that is the case
where C1 would be traded away, and it deserves its own decision rather than
riding along with the TTS one.

## Privacy policy status

**Safe to publish today, verbatim:** C1, C2, C3, C8.

**Needs changing today:**

- The "Third parties" section is false as written while F1 stands. Either fix the
  cause or narrow the sentence — it must name the font request.
- The "Exports" section should not be in the present tense until the feature
  exists.
- "Nothing you load here is sent anywhere" (`PrivacyView.vue:8`) is true of
  archive data and is the strongest sentence on the page. Keep it, and keep it
  scoped to *what the user loads* — that stays true even if remote TTS ships
  later, because dialogue text is not something the user loaded.

**Wording to prefer going forward:** replace absolute negatives about third
parties with a positive enumeration — "the app makes no network requests except
X and Y". That survives adding a dependency; "no third parties" breaks the first
time anyone adds a font.
